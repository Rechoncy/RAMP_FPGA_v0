# Ramp Studio

从 GitHub 下载源码后，请先阅读 [仓库使用说明](docs/仓库使用说明.md)。本仓库包含源码、测试和手册；本机 EXE/BIT 发布包、构建缓存及实验数据不纳入 Git，文中的 `release/` 路径需另行构建或获取交付包。

**软件触发调试（2026-09-20）：**新增“系统调试 → 触发调试”：单脉冲、高/低电平、有限/无限周期脉冲和失联保护。四路 125 MHz 固件经 JTAG 临时加载，USB FIFO 33 项、UART COM3 在 1M/115200 各 33 项实板数字检查及两种接口的真实 GUI 链路通过；748 项回归通过，1 项权限测试跳过。Flash 未改写。见 [操作说明](docs/软件触发调试.md) 与 [完整验证记录](docs/软件触发实板验证_2026-09-20.md)。

**复用 Flash 镜像：**在“板卡与连接 → Flash 固化与启动”选择“使用已有 MCS / BIN · 直接固化”，检查镜像后即可通过 JTAG 备份、固化和校验，无需原 `.bit` 或重新综合。支持地址 0 的连续单镜像，旧 `.bit` 流程保留。详见 [Flash 固化与启动](docs/Flash固化与启动.md)。

**需要全部本机文件时：**同一私有仓库通过 Release 提供完整工作区分卷，包含发布包、实验数据、历史归档、构建资料和虚拟环境；见 [完整备份与恢复](docs/完整备份与恢复.md)。普通 `git clone` 获取源码，完整快照需另下载 Release 附件。

**R2 USB FIFO 补测通过：**用户切换至 USB SLAVE 后，同一份 125 MSPS 固件完成 4096 帧连续查询、四路播放和满容量下载检查；每路 2048 段约 90 ms，约为 UART 1M 实测速度的 6.7 倍。选择 **USB FIFO · FTAE79DQ** 连接，无需波特率。本轮未烧写任何固件，见 [USB FIFO R2 实板结果](docs/USB_FIFO_R2实板验证_2026-09-17.md)。

**历史 UART 实板验证（2026-09-17，R2）：**当前板卡已临时 JTAG 加载 `09171830`：四路 10 位、125 MSPS、UART 九档 9600～1M 自动识别。3549 次命令交换无重试，四路播放期间切换连接及每路 2048 段下载通过；测试后均为空闲原码 512。Flash 未改写，掉电后恢复原 Flash 固件。新版软件与 `release/FPGA-XC7A35T-AutoBaud-20260917-R2/` 已同步，见 [UART 实板验证及使用方式](docs/UART实板验证_2026-09-17.md)。下列早期 200 MHz USB 记录是历史版本，不表示当前 DAC 仍运行在 200 MHz。

新增 **100 / 125 / 200 MSPS 输出采样率**。3PD5651E 使用 10 位、最高 125 MSPS，125 MSPS 下每点 8 ns；需重新构建并烧录，波形时长与原码不变。详见 [采样率设置及验证](docs/输出采样率与3PD5651E.md)。

**2026-09-17：**USB FIFO + UART 固件 `09171701` 已在当前四路 10 位达芬奇板上临时 JTAG 下载，85 项真实 USB 数字检查通过，每路 2048 段下载约 90 ms。未写 Flash，断电会恢复旧固件。DAC 上升沿、min −0.5 ns / max 1.0 ns 作为可保存的诊断默认值，不能替代实际 DAC / 走线参数。见 [本次实板验证与固件位置](docs/USB实板数字验证_2026-09-17.md)。

新增可选的 **FT232H 高速 USB FIFO**，同一份固件保留 UART，软件选择其中一个接口连接。在“板卡信息”配置，在“引脚配置 / XDC 预览”管理对应引脚。波形仍存于 BRAM，四路每路 2048 段，原有播放时长与精度规则不变。详见 [高速 USB 与串口](docs/高速USB与串口.md)。

Python 桌面上位机 + 200 MHz FPGA 独立多路 Ramp / 自定义函数播放器。本机已扩展为四路 10 位 DAC，界面分为“方案设计与保存”、“输出控制”总览和 DAC 1～4 单路大图，详见 [四路 DAC 操作及接线](docs/四路DAC并行输出.md)。支持 10/12/14 位并行 DAC（同一工程统一位数）。核心与可配置的 1～8 路 DAC 的数据寄存/转发时钟均为 200 MHz，使用同一个 MMCM 输出。原始 `Assistant_FPGA/` 工程保留；新固件、界面和生成脚本位于独立目录。

支持单端和差分参考时钟，可选 50 / 100 / 200 MHz 或手动输入；核心和 DAC 仍为 200 MHz。在“板卡信息”配置输入形式、频率与独立时钟 IO 标准，在“引脚配置”填写单端或 P/N 管脚。旧 50 MHz 单端配置保持兼容，换用新参考时钟须重新生成并烧写固件。详见 [参考时钟配置](docs/参考时钟配置.md)。当前工具链适配范围为 Xilinx 7 系列。

串口支持 **9600～1,000,000 baud 自动识别**，同一份新版固件无需为不同速率重复烧录。在“板卡与连接”断开、选择波特率、重新连接即可；软件发送同步序列后再读取设备能力。旧固定波特率固件需要先升级一次，旧版仍须选择匹配的速率。“板卡信息 → UART 上电默认波特率”只决定 FPGA 复位后的初始速率，不限制连接时选择。USB FIFO 不使用波特率；DAC 播放时钟不受串口速率影响。见 [UART 自动波特率](docs/UART自动波特率.md)。

支持自动读取已连接固件的波形容量，在设计页、DAC 单路与输出总览显示所需码段和设备上限。准备或下载前刷新能力并检查全部所选通道，超限时不写入新波形。离线配置预估与演示能力分别标注，不作为实板资源检测结果。已有支持 GET_INFO 的固件无需为此功能重烧；详见 [资源能力与下发检查](docs/资源能力与下发检查.md)。

新增可选 **分段线性插值**，四路仍保持每路 2048 段。14 位高斯示例在全部 28,000 个采样点上验证得到 139 段、最大差异 1 个原码，保留旧逐码保持方案行为。见 [14 位高斯分段插值操作与边界](docs/14位高斯分段插值.md) 和 [独立示例 JSON](examples/interpolation/14bit_gaussian_gate.json)。旧参考固件 `09133301` 不支持插值；新诊断固件 `09171701` 已包含该能力，但本次实板配置仍为四路 10 位。使用 14 位接口需按实际接线重新构建，不能直接下载 14 位方案到 10 位固件。更新软件不会自动烧写 FPGA 或 Flash。

左侧栏底部常驻显示 **LUT / FF / BRAM / DSP** 四项硬件占用百分比，切换页面时仍可查看。点击“硬件资源”打开完整报告，查看已用 / 总量、刷新或导入 Vivado 报告。报告来源、阶段、时间与配置是否一致会分别提示；默认发布固件参考不表示当前连接设备实测。详见 [板卡硬件资源占用](docs/板卡硬件资源占用.md)。

## 启动

单波形无限循环：在“方案设计与保存 → 波形库”的固定时长 Ramp 或自定义函数中，将“重复次数”选为“无限循环 · ∞”。保存并为 DAC 准备后，由一次软件或外部触发开始持续播放，点击“中止”停止。每轮复用同一份波形，只占一轮码段容量；运行中的额外触发不会重新开始波形。已连接固件须回报无限重复能力，否则程序在下发前阻止操作；已支持该能力的固件无需为此次界面更新重烧。详见 [使用手册](docs/软件详细使用手册.md)。

整表无限循环：进入“方案设计与保存 → 执行序列 → 固定时间表”，将“整表重复”选为“无限重复 · ∞”。保存后在 DAC 页下载、布防、触发，一次触发后持续循环，点击中止停止。此选项需要支持无限重复的新 FPGA 固件；详细说明与示例见 [执行序列使用说明](docs/执行序列使用说明.md)。

推荐双击 `release/Ramp Studio.exe`，或使用已经指向 EXE 的桌面/开始菜单 **Ramp Studio** 图标。图标已嵌入 EXE，无需额外安装 Python、Qt 或 NumPy。

正常退出时自动保存设置与编辑进度，下次启动恢复板卡 / Flash 输入、波形 / 序列 / 扫描草稿、时间单位、DAC 分配、Debug 待提交原码及上次页面。会话文件为 `user_data/desktop_session.json`；未完成或无效参数也保留为草稿。要更新供 DAC 使用的方案版本，仍需点击“保存方案”后重新准备。启动保持未连接，不自动下载、布防或应用静态输出；保存失败时窗口保留并显示原因。

左侧 FPGA 信息下方提供 **“全局保存 / 全局导入”**。全局保存将当前方案库、编辑草稿、板卡 / 引脚 / 时钟 / UART / Flash 设置、上电方案快照、DAC 分配、Debug 待提交值及界面设置导出为一个 `.ramp-workspace` 文件。全局导入在未连接状态下进行，确认包摘要后替换本地方案和设置，导入前自动备份到 `user_data/archive/workspaces/`，随后重新打开工作区并保持未连接。草稿继续作为草稿恢复，使用前仍需保存方案并为 DAC 准备。此文件不含 EXE、Vivado、BIT、硬件 Flash 内容、历史归档、资源报告或设备确认缓存；本机这些历史资料保留。详细步骤见 [使用手册第 15 节](docs/软件详细使用手册.md)。

迁移到 Windows 10/11 x64 电脑：解压 `release/Ramp-Studio-Windows-x64.zip` 后双击 EXE。保留实验时，将现有 EXE 旁的 **整个 `user_data` 文件夹一起复制**。串口控制需要 USB-UART 驱动，FT232H 高速 USB 需要 Windows x64 FTDI D2XX 驱动；生成固件时需要在板卡页面选择新电脑的 Vivado 路径。

本工作区日常启动使用 `release/user_data`；根目录 user_data 供源码模式使用。无需复制整个工程。具体复制清单见 [迁移到其他电脑](docs/迁移到其他电脑.html)。旧构建记录和旧固件已归档，清理后的目录用途见 [目录与归档说明](docs/目录与归档说明.html)。

[便携版使用与迁移说明](docs/Windows便携版说明.md) 包含数据位置、构建输出及诊断方法。执行 `Build-Executable.ps1` 可以从源码重新打包。`Start-RampStudio.cmd` / `.ps1` 优先启动 EXE，未打包时使用源码环境。

源码开发仍可运行 `Setup-RampStudio.ps1` 后执行 `.\.venv\Scripts\python.exe -m host.app`。本机使用 Python 3.12 专用环境，避免与 Conda 的 Qt/VC 运行库混用。

## 先体验演示模式

1. 在左侧“板卡与连接”中选择“演示设备 · 无需硬件”，点击连接。
2. 在“方案设计与保存”中选择“单幅度 Ramp”，设置初始/结束码、目标码和三个时长并保存；也可选择三段自定义函数。
3. 进入 DAC 页面，展开“方案与触发设置”选择已保存方案，点击“准备 DAC n”。总览可勾选多个 DAC，点击“准备所选”。外部模式在“更多操作”中模拟输入；软件模式点击“软件触发”。单路大图支持已加载、本地方案和版本对比。
4. 运行状态、完成次数和输出回报码随状态刷新。演示模式使用系统时间模拟，不代表真实硬件的时序测试。

保存的方案内容变更后，须重新下载确认才可按新方案布防；编辑草稿（包括切换时间单位）只改变待下载设置，不会自动修改硬件输出。运行中的配置不会被覆盖。断开电脑连接不会中止硬件内已经提交的序列；需要中止时先点击“中止”。串口中止不是具有确定响应时间的硬件急停。

## 单 DAC 多波形执行序列

“方案设计与保存”新增 **执行序列** 页签：固定时间表将多个保存波形及等待段提前编译为一条完整码流；事件序列允许每一步共用或分别选择外部触发输入、上升/下降沿，以及门控返回后推进。步骤保存波形快照，随后在 DAC 页面选择并下载。

固定时间表兼容现有 200 MHz 采样播放器；事件/门控步骤需要新版 FPGA 序列固件。当前四路每路共享 2048 码段，最多 64 步，未就绪/忙时事件不排队。详见 [执行序列使用说明](docs/执行序列使用说明.md)。

## 触发步进扫描

“方案设计与保存 → 触发步进”可设置起始码、步长和点数，每次外部边沿推进一点，保持至下一次触发。支持正/负步长、1～65535 点、末点保持或循环、各路独立/共用输入以及上电快照。第 1 次输出起始码；新功能需升级一次 FPGA 固件，日常修改只需准备扫描方案。详见 [触发步进说明](docs/触发步进使用说明.md)。

## 波形与方案管理

**掉电保存与重复外部触发**：在“板卡与连接 → Flash 固化与启动”纳入各 DAC 的保存方案，重新构建并固化后，上电恢复波形并自动布防。普通串口下载仍只写 RAM，永久修改需要重新固化。新版固定时长外部触发完成后也自动重新布防，无需每次发送 ARM。[操作说明](docs/Flash固化与启动.md)。

**电平门控**：方案设计页选择“电平门控”，保存后在 DAC 页面选择并下载该方案，上升沿播放进入段，高电平保持目标码，下降沿播放返回段并自动重新布防。提前下降沿从当前码线性返回；固定保持时长和重复次数在此模式不生效。支持 Ramp 和三段函数，实际设备需要重新生成、烧录新版固件。[操作与边界说明](docs/电平门控.md)。

时间输入右侧可独立选择 **ns / µs / ms / s**；切换单位保留填写的数值，例如 `70 ms → 70 µs`，实际时长按新单位计算，保存并重新下载后生效。预览轴自动选择合适单位，函数中的 t/T 仍以秒计。详见 [时间单位](docs/时间单位.md)。

左侧 **Debug 静态输出** 支持选择 DAC 并输出静态原码，提供设备回读、返回初始码、输出数字中点和中止操作。无需触发，10/12/14 位范围随设备能力变化；应用后运行波形需重新下载。详见 [Debug 静态输出](docs/Debug静态输出.md)。

- 单幅度 Ramp：初始码 → 一个目标幅度码 → 初始码，设置初始/结束码、目标码和三个时长；中止码独立设置。
- 自定义函数：默认分为进入、保持、返回三段，独立设置初始码 I、目标码 A 和三个时长；提供半高斯、余弦平滑、线性模板，进入与返回公式可独立编辑。t/T 为每段的时间/时长，单位秒。旧整段函数方案保留原语义。详见 [三段自定义函数](docs/三段自定义函数.md)。
- 软件每 5 ns 采样并四舍五入。默认逐码保持对重复原码无损压缩，FPGA 精确播放取整结果；显式选择分段线性插值后，FPGA 每拍重建原码，上位机检查相对于完整取整采样的全部点差异。当前四路每路最多 2048 段（其他配置以 INFO 回报为准），超限报错，不自动放宽精度。固定时长模式单轮最长 1 秒，可指定 1～65535 次或无限循环；门控模式进入和返回合计最长 1 秒，外部高电平保持不计入此限额。
- 输出选择 DAC 1～已配置的 DAC 数量，各路可同时播放不同波形。提交后及结束时保持初始码，中止时使用中止码；其他通道保持自身配置；未包含上电方案的固件复位时为数字中点：10/12/14 位分别为 512/2048/8192。原 10 位板卡码 0 电压最大，512 接近零，1023 为最小负电压；不做电压换算。
- 波形预览默认按显示波形自动缩放 DAC 原码纵轴，使用整数刻度并处理常值及量程边界；版本对比共用同一纵轴。各通道缩略图单独缩放，鼠标停留可看范围，不能只按图高比较幅度。缩放不改变原码、时间或下发数据，无需更新固件。
- 图形仍为抽样预览，单波形通常取约 1600 个位置并补充必要边界；“完整离散检查”和下载遍历全部采样点。门控保持段仅为示意，实际时长由外部输入决定。后台执行完整检查与下载，保留界面响应。
- `user_data/profiles/` 保存 JSON 方案；可搜索、复制、导入、导出及归档。`user_data/archive/` 保留归档方案，可重新导入恢复。
- `user_data/logs/` 保存下载快照（含函数与输出通道）、配置 ID、命令结果、状态变化及错误。
- “波形库”编辑器只提供单幅度 Ramp 和自定义函数，不再显示旧 FM 扫描；“触发步进”使用独立子页。历史分段方案标为只读；符合“进入—保持—返回”三段结构时可显式转换为新的 Ramp 副本，检查后保存使用。原文件保留，不自动转换输出。

位数切换、数据位映射及原码规则见 [DAC 位数设置](docs/DAC位数设置.md)。初始值、触发接线和增加 DAC 的操作见 [初始值、触发与 DAC 扩展](docs/初始值触发与DAC扩展.md)。完整说明、函数示例及 DAC 接口映射见 [函数波形与 DAC 选择](docs/函数波形与DAC选择.md)。新项目只编译本目录独立 RTL，不引用 `Assistant_FPGA/` 的源码或 IP。原项目仅为参考接线资料。

界面没有 ADC，预览与回报码均不代表实测模拟电压。

波形容量是固件已分配的每路、每个存储 bank 的槽位，活动和待提交 bank 不相加，各路不借用。UART 不回报具体 FPGA 型号或 LUT/FF/物理 BRAM 总量；这些数据须看对应固件的 Vivado 构建报告。触发步进只写配置参数，65535 点属于协议上限，不是采样表槽位数。

界面按连接、设计保存、通道执行和 Debug 调试划分职责。窄窗口使用折叠方案管理和可换行表单；序列只显示当前模式与步骤需要的参数。单路、多路和 Debug 控制固定可见，切换序列会保护未保存草稿。

## 板卡与连接

该页面集中管理设备连接，并包含七个配置标签页。保存、导入、导出和 XDC 操作固定在底部，切换页面保留已填写内容：

| 页面 | 功能 |
|---|---|
| 板卡信息 | 板卡名称、FPGA 型号、参考时钟、UART 上电默认波特率、DAC 位数与数量、触发数量、Vivado 路径、统一 IO 电气设置；硬件占用统一从左侧栏底部查看 |
| 引脚配置 | 独立大表格，按 DAC / 触发 / 通信筛选，编辑管脚与逐引脚 IO 标准 |
| XDC 预览 | 格式与重复引脚检查、缺失项提示、约束预览和导出 |
| 构建与日志 | 生成时钟 IP、综合、核心布局布线检查，以及完整实现与 bitstream |
| DAC 时序 | 共用默认的最小/最大延迟与采样边沿，以及各路独立覆盖 |
| 触发接线说明 | 接线步骤、当前触发引脚、布防和边沿行为 |
| Flash 固化与启动 | Flash 型号/容量/SPI、上电方案快照、MCS/BIN、备份、写入校验和启动检查 |

默认沿用原工程的 DAC 与触发管脚。**UART RX/TX 默认未分配，DAC 的 `set_output_delay` 最小/最大值默认未填。** 在页面中依据实际板卡和 DAC 资料设置，然后保存或导出为板卡 JSON。

可为多块板卡分别保存/导出 JSON，按需导入；不会替换原工程的 XDC。全量引脚与时序参数未填时可以生成草稿、做综合或核心检查，不能选择完整 bitstream 流程。

“格式正确”并不能证明该管脚存在、Bank 电压匹配或时序值正确。最终由准确器件型号、原理图、DAC 数据手册以及 Vivado DRC/时序检查共同确认。输出时序值应包含 DAC 建立/保持要求和板级走线差；可在“DAC 时序”分别覆盖各路参数。旧板卡 JSON 的端口名称会迁移到可扩展总线名称，原物理引脚值保留；必须重新生成 XDC 和固件。

Vivado 默认路径：`E:\Software\Xilinx\Vivado\2023.1\bin\vivado.bat`。每次构建输出到唯一的 `user_data/builds/studio_<时间>/`，日志在界面中滚动显示。不会自动烧录开发板。

## 固件边界

| 项目 | 当前实现 |
|---|---|
| 已验证器件 | `xc7a35tfgg484-2`，Vivado 2023.1 |
| 核心时钟 | 参考输入默认 50 MHz，经 MMCM 产生 200 MHz |
| UART | 8N1，默认 115200 baud，可在构建时选择最高 1,000,000 baud；电脑连接速度须与已烧录固件匹配 |
| DAC 接口 | 1～8 路 10/12/14 位并行数据；专用 ODDR 转发 200 MHz 时钟，周期 5 ns |
| 新模式更新间隔 | 固定 1 拍 / 5 ns；旧分段执行器仍为最短 16 拍 / 80 ns |
| 新模式存储 | 每路独立双 bank；四路配置每路 2048 个 B+32 位码值/拍数描述符，4 项 FIFO 预取 |
| 段时长 | 32 位更新次数；计数范围随实际更新间隔变化 |
| 外部触发 | 1～8 个输入；固定时长按所选边沿启动，电平门控按上升进入 / 高电平保持 / 下降返回 |
| 软件触发 | 支持按通道掩码在同一核心时钟发出启动信号；串口通信延迟不作为精确定时依据 |
| 配置 | 双 bank 缓存，顺序下载全部段后 COMMIT，布防/运行时禁止修改 |
| 运算 | 新模式由 Python 完整采样取整，FPGA 按拍播放；旧模式保留插值执行器 |
| 复位 | 上电及失锁保持复位；按时钟域同步释放。普通镜像上电输出数字中点码，需重新下载；带上电方案的镜像完整配置后恢复快照，外部触发方案自动布防。运行中的逻辑复位不等同于重新加载镜像 |
| 中止 | 新模式返回已提交的中止码；旧模式使用已提交的中止码与 FM 初始码 |

新模式支持每 5 ns 更新 DAC 码值，实际模拟带宽和接收能力仍由 DAC 与后级电路决定。独立触发输入须稳定跨越同步采样窗口；建议脉冲高/低至少 20 ns，并通过板上测量确定可靠最小脉宽和固定响应延迟。

从旧版 50 MHz DAC 固件升级时，应重启上位机，并从“板卡与连接”重新生成 XDC 与工程、完成时序检查并烧录新固件。不能继续使用旧版指向 MMCM `CLKOUT1` 的 DAC 派生时钟约束；新版使用 `CLKOUT0`。连接旧固件时，界面仍会按设备真实返回能力显示 50 MHz，而不会仅修改显示文字。

本版支持完整序列触发和电平门控。已支持多 DAC 同时播放独立序列；外部点表文件导入、闭环采集和自动批量扫描界面尚未实现。Python SDK 已可用于编写实验间扫描脚本。

## 跨 FPGA 移植

`rtl/common/` 不包含厂商原语。时钟、复位和 DAC 时钟输出位于 `rtl/platform/xilinx_7series/`。目前 GUI 构建器允许 Xilinx 7 系列器件，并由 Vivado 校验目标；实际验证目标仅为当前 Artix-7。

更换 7 系列板卡要更新参考频率、引脚、电压和 DAC 时序并重新编译。UltraScale、Intel、Gowin 等需要增加平台适配器及对应构建工具；不能使用同一 bitstream。上位机按 GET_INFO 返回的频率、更新间隔、容量编译参数；当前桌面版支持 10/12/14 位并行 DAC，同一工程统一位数。

## Python 脚本示例

```python
from host.model import Profile
from host.protocol import Device, SerialTransport, ARM, TRIGGER, ABORT
import time

device = Device(SerialTransport("COM5"))
try:
    p = Profile(mode="function", function_layout="single", channel=0, trigger="software", initial=512, safe=512,
                function="I - 400*sin(2*pi*t/T)", function_ms=0.01)
    device.upload(p)
    device.command(ARM)
    device.command(TRIGGER)
    while device.status()["state"] != 3:
        time.sleep(0.1)  # 只用于读状态，波形时序由 FPGA 完成
finally:
    device.close()
```

异常时是否发送 ABORT 由实验脚本明确决定；关闭串口不会自动停止硬件。接口详见 [docs/协议-v1.md](docs/协议-v1.md)。
