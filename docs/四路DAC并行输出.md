# 四路 DAC 独立并行输出

本版使用四套独立的波形配置、双缓冲存储和播放状态机。四路可同时输出不同的 Ramp、三段函数或静态码；下载或中止某一路不覆盖其他路。四路 DAC 和核心共用 200 MHz 时钟，采样周期 5 ns。同一固件统一使用 10、12 或 14 位，当前实板配置为四路 10 位。

## 使用

1. 在“方案设计与保存”中保存波形或执行序列。
2. 打开 DAC 1～4，展开“方案与触发设置”，选择本地方案。可沿用方案触发，也可为当前 DAC 单独设置输入和边沿；事件序列保持每步独立触发定义。
3. 单路点击“准备 DAC n”；多路返回“输出控制”，勾选通道后点击“准备所选”。程序先验证，按需下载、回读确认，再布防。只有参数或版本变化时才重新下载。
4. 全部为软件触发时可执行分组“软件触发”。外部同步使用同一物理输入和边沿；也可为各通道或事件步骤使用不同输入。
5. 总览显示已加载缩略图，点击进入单路大图，可切换本地方案与版本对比。选择或修改本地方案不会覆盖已加载曲线或立即改变硬件。
6. 中止所选和单路中止作用范围明确；全局中止在“更多操作”中。静态码在左侧 Debug 页选择对应 DAC 后提交。

进入单路后，操作只作用于当前 DAC；返回总览保留原有勾选。勾选只选择操作对象，不开关通道。中途下载失败时，已提交通道可能更新，逐路确认快照与状态仍保留，不继续执行最终分组布防。

方案、分配、逐通道触发设置和确认快照分别保存在 `user_data/profiles`、`parallel.json` 与 `loaded_waveforms.json`。重连真实串口只在有效配置 ID、通道与位数匹配时复用快照，未知设备配置不显示推测波形。完整波形目前不能从设备反读；蓝色实线是确认快照计算后的原码预览，不是模拟电压实测。

Flash 页使用自己的 DAC 勾选和 `flash_selection.json`，与输出操作范围无关。普通准备不写 Flash；永久修改需要重新纳入、构建、固化，详见 [Flash 固化与启动](Flash固化与启动.md)。

## DAC 3 / 4 接线

管脚来自用户提供的 Assistant_main.xdc 中已注释的 `mag_z` 与 `mag_y` 两组。迁移后不再依赖原 FPGA 工程；生成器和独立工程使用下表保存的映射。信号电平约束与参考文件一致，LVCMOS33。

| 信号 | DAC 3（原 mag_z） | DAC 4（原 mag_y） |
|---|---|---|
| D0 | N22 | N19 |
| D1 | M22 | N18 |
| D2 | M21 | M20 |
| D3 | L21 | N20 |
| D4 | K22 | J21 |
| D5 | K21 | J20 |
| D6 | J22 | G20 |
| D7 | H22 | H20 |
| D8 | G22 | L18 |
| D9 | G21 | M18 |
| 时钟 | E19 | F21 |

扁平端口分别为 DAC 3：`dac_data[29:20]`、`dac_clk[2]`；DAC 4：`dac_data[39:30]`、`dac_clk[3]`。DAC 1/2、UART RX U5 / TX T6、触发 F13 / F14 保持已有映射。

## 容量与兼容性

当前四路固件每路最多 2048 个连续码段，并非仅 2048 个采样点。同一原码持续多个 5 ns 周期时只占一个码段。四路各自计算容量；不会自动降采样、缩放原码或缩短波形。函数编译器的全局上限仍为 8192，实际下载按设备回报的每路上限检查。

通用构建默认存储分配：1 路 8192 段/路、2 路 4096 段/路、3～4 路 2048 段/路、5～8 路 1024 段/路。不同 FPGA 的实际资源与时序仍需重新实现验证。旧版分段/FM 双输出协议不用于独立多路固件，请使用 Ramp 或自定义函数。

迁移到其他电脑时可在硬件页面导入随包提供的 `四路DAC板卡.json`；已有实验方案请连同 `user_data` 文件夹迁移。

新上位机可连接旧的单播放器固件，此时批量准备不可用，仍可进入对应 DAC 单路操作。两路演示设备保留旧模式兼容测试；将硬件页面的 DAC 数量设为 4 后连接演示设备，可演示四路并行。

## 协议扩展

仍使用 v1 的 32 字节 CRC 帧。INFO 功能标志 byte 17 新增 bit 2（值 4）表示独立多路；早期四路版标志为 7，新增固定时长自动布防后为 15，包含上电方案时为 31；board_id 为 2。INFO byte 13～14 回报每路最大码段数。

- `0x40 SELECT_CHANNEL`：payload byte 0 为从 0 开始的 DAC 编号。后续 STATUS、BEGIN/RUN/COMMIT、ARM/TRIGGER/ABORT/DISARM 操作该通道。BEGIN 中的通道号必须与所选通道一致。
- `0x41 GROUP_COMMAND`：payload byte 0 为 ARM=0x20、TRIGGER=0x21 或 ABORT=0x22；byte 1 为参与通道掩码，四路全选是 0x0F。空掩码、越界掩码拒绝。布防/触发在发出命令前检查全部参与通道，避免部分启动；精确重发同一帧返回缓存响应。
- 状态回读保留各自配置 ID、当前码、完成次数与门控阶段。串口逐路轮询不能测量 5 ns 级同步误差。

验证范围见本次实板报告。没有 DAC 型号与测量设备时，数字仿真、内部时序和串口回读不能代替外部 DAC 建立/保持时序及模拟输出的测量。
