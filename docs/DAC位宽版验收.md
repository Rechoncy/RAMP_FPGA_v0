# 10 / 12 / 14 位 DAC 验收

日期：2026-09-10。器件 `xc7a35tfgg484-2`，Vivado 2023.1，50 MHz 参考输入，核心与 DAC 时钟均为 200 MHz。

## 软件与 RTL

完整测试 **55 passed**。修正未分配管脚的 IO 标准输出后，相关主机、位宽、GUI 和扩展用例复验 **36 passed**。

- 三种位宽均验证原码 0、最大码、中点、上半区高位码、0.5 LSB 四舍五入、结束返回和中止码。
- RTL 在 8 路 DAC / 8 个触发输入下逐路播放，检查重复边界、触发选择、完整 u16 状态回报以及越界拒绝，防止高位被截断。
- 波形缓存包含位宽；方案 JSON 保存位宽；SDK 拒绝设备与方案位宽不一致。
- GUI 验证 14 位范围、保存/载入、14→10 时数值保留及越界报错、10→14 恢复，以及设备连接期间不采用本地草稿位宽。
- 引脚在修改位宽时按通道及数据位身份迁移，新增高位不猜测物理接线。
- 10 位旧分段/FM 功能继续测试；12/14 位仅开放单幅度 Ramp 和函数播放器。

## Vivado 核心实现

全部为 **8 DAC / 8 触发输入**，同一工程统一位宽。

| DAC 位数 | 10 | 12 | 14 |
|---|---:|---:|---:|
| 工程 | `studio_width10` | `studio_width12` | `studio_width14_v2` |
| WNS / ns | +0.016 | +0.150 | +0.115 |
| WHS / ns | +0.058 | +0.063 | +0.048 |
| Setup / hold 失败端点 | 0 / 0 | 0 / 0 | 0 / 0 |
| 时序端点数 | 10321 | 10106 | 10241 |
| LUT | 1791 | 1729 | 1739 |
| 寄存器 | 3259 | 3178 | 3214 |
| BRAM tiles | 22.5 | 23.5 | 24.5 |
| CDC safe / unsafe / unknown | 9 / 0 / 0 | 9 / 0 / 0 | 9 / 0 / 0 |

工程均位于 `build/`，最终报告在对应 `core_route_check/`。数字来自最终 `report_timing_summary`，不是中途估计值。更换器件、引脚或时序约束后需重新验证。

14 位首轮 `studio_width14` 在 IO 放置阶段失败：没有管脚位置的端口也没有应用已选的 IO 标准，Vivado 无法将这些端口放入已有电压标准的 Bank。生成器已改为独立设置 IO 标准与管脚位置，`studio_width14_v2` 重新综合及布局布线通过。没有随意添加物理引脚或降低 DRC 严重性。

10/12 位报告使用修正前的 XDC 草稿（未定位端口仍为 DEFAULT），14 位 v2 使用修正后的草稿；通用 RTL 相同，各报告仅代表自己的约束快照。当前生成器对所有位宽均应用所选 IO 标准。

## 时钟仿真与边界

`studio_width14` 的 XSim 使用生成 MMCM/UNISIM ODDR 模型，参数为 8 DAC、8 触发、14 位。结果 **PASS DAC200**：周期 5 ns，高电平 2.5 ns，全部时钟对齐，每路数据寄存器接收不同的接近 16383 的高位码。IO 标准生成修正不改变该 RTL 或时钟模型。

仍未填入实际新增数据位、触发及 UART 管脚，也未确认 DAC 的 min/max 板级延迟。14 位 v2 的 DRC 保留未定位管脚 UCIO-1 及部分总线未锁定的 PLIO-3；10/12 位历史草稿另保留 NSTD-1。因此没有生成或烧录 bitstream，没有验证实际 DAC 的模拟电压、接收带宽或零点。

每个 bank 仍为 8192 个连续码段，位宽增加不扩大码段容量。原码不自动缩放；同一工程不混合不同位数 DAC。使用规则见 [DAC 位数设置](DAC位数设置.md)。源码及报告哈希记录在 `build/validation_widths_manifest.json`。
