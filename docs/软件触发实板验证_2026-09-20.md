## 实板与界面链路

`scripts/verify_trigger_debug.py` 在 USB FIFO 实板完成 **33 项检查**，详见固件交付目录的 `hardware_usb.json`：

- 原逐码保持和分段线性模式，四路共享虚拟输入同时进入目标原码。
- 高电平保持、下降沿返回、自动重新布防，以及进入阶段提前下降。
- 重复设高不产生多余上升沿；布防时拒绝切换输入来源。
- 固定波形重复、忙时边沿计数、指定 20 次脉冲结束。
- 输入 1 只推进 DAC 1/3，输入 2 只推进 DAC 2/4；周期脉冲推进扫描至末点。
- 输入 1 的固定事件步骤推进至输入 2 的插值门控步骤，返回后序列循环等待输入 1。
- 无限脉冲运行与主动中止。
- 高电平保持期间停止心跳 3.3 秒后，FPGA 自主中止全部 DAC 并恢复物理来源。

另用真实 Studio 界面、DeviceWorker、USBTransport 和 FPGA 完成按钮链路：接管全部输入 → 四路布防 → 点击高电平 → 四路目标值回读 → 点击低电平 → 返回并重新布防 → 结束调试。`gui_hardware.json` 记录各阶段设备状态，GUI 未出现操作错误。

这些是数字状态/原码验证，没有示波器采样，不代表实际 DAC 模拟电压精度或引脚波形测量。首轮 USB 验证时独立 CH340 UART 未接入；随后用户切换接口，完成下述 UART 实板补测。

## 协议与恢复

INFO 扩展能力 byte19 bit5；新增 0x60～0x63 分别配置虚拟输入、设置电平/脉冲、状态/心跳和结束调试。状态区分发生器边沿计数与各 DAC 的完成/忽略计数。旧固件明确拒绝新命令。详细字段见 [协议-v1](协议-v1.md)。

切换来源要求全部通道停止。调试期间物理边沿只在未接管输入继续生效。掉电、复位默认物理来源；保存设置不会自动接管输入或启动输出。结束调试和超时保护中止全部 DAC，使用各自已提交的中止码。

修复了超时中止与请求同拍时的请求保留问题，避免双接口路由器等待一个已经被丢弃的请求。断线后即使主动中止没有应答，上位机也会释放连接，由 FPGA 心跳超时兜底，不留下虚假的“已连接”状态。

## 已布防波形直接调试修复

旧发布版要求先接管输入再布防，导致用户在输出页先布防后，软件触发按钮不可用。新版上位机允许直接发送：先读取所有通道状态，临时取消等待中的布防，接管输入，恢复原布防通道，等待就绪后再发送。不会重新下载或替换波形；正在播放时拒绝切换。首次切换短暂经过中止码，扫描/事件序列进度重置。底层固件的来源切换保护仍保留，无需重烧 BIT。

- 触发与接管专项 16 项测试通过，涵盖保留通道选择、运行中拒绝、非法参数、连接所有权、重新布防失败后停止、GUI 可用性和 USB/UART 线级仿真。
- 实板使用当时连接的 USB FIFO，在真实 Studio 界面加载用户已有 `Dipole_Ramp_Rydberg_Gaussian` 到 DAC 1：物理来源下先布防，再直接点击高电平，回读运行中原码 0；点击低电平后返回 355、完成一次并重新等待触发。整个接管和触发过程配置标识不变，其他三路保持空闲。
- 结束调试后 DAC 1 空闲于其方案中止码 355，其他三路空闲于 512，恢复物理输入。没有修改用户方案文件，没有烧写 FPGA 或 Flash。证据：`build/trigger_debug_20260920/gui_armed_handover.json` 和同名日志。
- 本次新交互的实板检查使用 USB FIFO；UART 没有接入，因此新接管流程尚未在 UART 实板复测。此前 UART 33 项结果对应原命令链路，不能替代本次接管流程验证。
