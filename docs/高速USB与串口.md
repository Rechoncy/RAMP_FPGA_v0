# 高速 USB FIFO 与 UART 串口

本版增加 FT232H 同步并行 FIFO 通信和批量上传，保留 UART 串口。按用户要求，DDR3 扩展已经撤除，软件不再提供 DDR3、MIG 或外部波形池设置。

**2026-09-17 更新：**双接口固件 `09171701` 已通过 JTAG 临时烧写和真实 USB 数字联调，85 项检查通过；每路 2048 段下载约 90 ms。Flash 未改写，断电会恢复旧固件。DAC 暂用上升沿、min −0.5 ns / max 1.0 ns 的诊断假设，具体范围见 [USB 实板数字验证](USB实板数字验证_2026-09-17.md)。

## 1. 存储和播放保持原有规则

- 波形存储使用片内 BRAM。四路配置每路、每 bank 为 **2048 段**，活动与待提交 bank 不相加。事件步骤共用本通道波形池。
- 原逐码保持最短 **1 拍 / 5 ns**；线性插值最短 **32 拍 / 160 ns**，每拍仍输出一个 DAC 原码。
- 不存在 DDR3 方案的 256 拍 / 1.28 µs 下限；不会为了传输接口而改变波形时长、位数、原码或允许误差。
- 14 位高斯可以继续使用已验证的 BRAM 插值方案；USB 只改变下载路径，不改变触发与播放时钟。

## 2. 一份固件，两种连接方式

启用 USB 后，生成的固件同时保留 UART。电脑连接 **USB SLAVE / FT232H** 时，软件设备列表选择 `USB FIFO · 序列号`；连接 **USB UART / CH340** 时选择对应 `COM` 端口和所需波特率（旧固定速率固件须匹配原值）。

在软件中先断开当前连接，再选择另一个接口连接即可，切换不需要重新生成或烧录固件。新版串口固件通过连接时同步自动识别九档速率，无需为每档重烧；旧固件先升级一次，见 [UART 自动波特率](UART自动波特率.md)。串口波特率最高 1,000,000 baud；USB FIFO 不使用波特率，因此选择 USB 时隐藏波特率输入。

两个物理接口的命令经过同一控制器，应答返回请求来源。**同一时刻只使用一个上位机控制端配置板卡**，不支持两个客户端交错上传同一路波形或争用当前 DAC 选择。切换传输入口后应重新读取设备能力和实际状态，软件不把旧连接记录当作新下载确认。

没有启用 USB 的旧 UART 固件仍可使用；USB 能力、批量能力均由实际固件回报，不以勾选板卡设置代替固件升级。

## 3. 板卡信息及 XDC

1. 打开 **板卡与连接 → 板卡信息 → 高速 USB 通信**。
2. 勾选 **增加 FT232H USB FIFO 接口，同时保留 UART 串口**。
3. 展开 **USB 接口参数与达芬奇引脚模板**，点击 **应用 USB 引脚**。
4. 点击 **查看 USB 引脚**，在独立引脚页逐项核对。已有引脚冲突会报错，不覆盖 DAC、触发或 UART 接线。
5. 在 **XDC 预览**检查 USB 的 60 MHz 时钟、引脚和输入输出延迟；在 **构建与日志**生成工程、综合及检查时序。

达芬奇 V2.1 的模板如下。`input/output` 方向以 FPGA 为参照。

| 信号 | 管脚 | 方向 / 用途 |
|---|---|---|
| usb_clk | Y4 | input，FT232H 60 MHz CLKOUT |
| usb_data[0:7] | AB5、AA4、AB3、AA3、AB2、AB1、AA1、Y1 | 双向，D0～D7 |
| usb_rxf_n | W1 | input，接收非空，低有效 |
| usb_txe_n | AA5 | input，可发送，低有效 |
| usb_rd_n | V4 | output，读使能，低有效 |
| usb_wr_n | Y3 | output，写使能，低有效 |
| usb_oe_n | U3 | output，FT232H 驱动数据总线，低有效 |
| usb_siwu_n | V3 | output，本实现保持非有效 |
| uart_rx / uart_tx | U5 / T6 | 原串口，独立于 USB FIFO |

USB 独立 IO 标准默认 LVCMOS33，不改变其他接口标准。FT232H 同步 FIFO 默认输入延迟 min/max 为 0/9 ns，输出为 0/7.5 ns；来自 [FT232H 数据手册表 4.1](https://ftdichip.com/wp-content/uploads/2024/09/DS_FT232H.pdf)，更换板卡应计入走线偏斜。跨时钟 FIFO 的 Gray 指针路径单独约束，不通过整体时钟域 false path 掩盖路径。

生成的 XDC 对 USB 数据和 RD# / WR# / OE# 输出使用 `SLEW FAST`，以满足 60 MHz 接口时序；不会改变 DAC 引脚的转换率或放宽上述延迟要求。USB 数据、控制和总线方向输出使用 IO 寄存器；接收侧设置两字节缓冲并预留下一拍空间，200 MHz 侧另有一级字节缓存。批量校验在控制器的准备周期内完成，均不改变波形存储数量和播放节拍。

更换板卡时可导入/导出板卡 JSON 或全局工作区，逐项改引脚、时钟和 IO 标准，然后重新构建。USB 管脚会自动进入生成的 XDC。FPGA 系列、FTDI 芯片或物理协议不同可能需要新适配器，不能只修改管脚名称。

## 4. 驱动和实际速度

Windows 需要安装 FTDI 官方 x64 D2XX 驱动，FT232H 的 EEPROM 需允许同步 245 FIFO 模式。程序只枚举 FT232H 数据接口，也排除设备描述为 Digilent / JTAG 的 FT232H 下载器，不自动安装驱动或改写 EEPROM。

USB FIFO 的物理总线是 8 bit / 60 MHz。厂商标称速度不等于应用层实测下载速度；实际速度受 USB 调度、CRC 帧、应答及控制器写入开销影响。9 月 17 日本机实测每路 2048 段约 90 ms，描述符有效吞吐量约 136 kB/s，包含 BEGIN / COMMIT 应答，不含波形编译；不是标称总线峰值。

## 5. 协议与兼容

32 字节帧及 CRC16 不变，INFO payload[19] bit1 表示 RUN_BATCH，bit2 表示 USB FIFO 能力。payload[22] 为批量版本 1，payload[23] 为每帧最多 3 段。

`RUN_BATCH (0x36)` 的 payload 为：起始索引 u16、数量 u8（1～3）、保留 0，随后 `数量 × (原码 u16 + 持续拍数 u32)`，其余字节为 0。固件先验证整批，再写待提交 bank，上传全部成功后仍需 COMMIT。

USB 采用最多 16 帧 / 512 字节的有界传输窗口，逐帧检查序号、CRC 和状态。窗口失败不盲目重发、不误提交半份波形。UART 保持逐帧应答；不支持新能力的旧固件继续用旧逐段命令。

曾使用未发布 DDR3 测试固件或启用 DDR3 的测试 JSON 会被明确拒绝，避免错误解释其容量；请使用本版 BRAM 配置重新构建。

## 6. 2026-09-16 开发验证记录

软件与 RTL 回归共 648 项：**647 通过，1 项因 Windows 创建符号链接权限（错误 1314）跳过，0 失败**。链接拒绝策略和真实 NTFS 目录联接测试通过；没有为测试修改系统权限。覆盖旧 UART、USB 字节 FIFO、0/9 ns FT232H 输入延迟边界、实际控制器批量上传、非法整批原子拒绝、DAC 隔离、无 USB 时钟时 UART 可用，以及不复位切换接口。USB 专项 11 项全部通过。

Vivado 2023.1 对 **XC7A35T、四路 10 位、两触发、50 MHz 单端参考、200 MHz 核心 / DAC、60 MHz USB** 完成综合和布局布线检查。最终 setup WNS 为 **0.000 ns**、TNS 为 0，hold 裕量 **+0.058 ns**，脉宽裕量 +1.370 ns；USB 域 setup / hold 为 +1.146 / +0.082 ns。核心建立时序是报告精度下的边界通过，没有可宣称的额外裕量。不能推广至 14 位、更多通道或其他器件；修改硬件配置后应重新构建检查。

| 布局布线后资源 | 已用 / 可用 | 占用率 |
|---|---|---|
| LUT | 12,946 / 20,800 | 62.24% |
| FF | 16,240 / 41,600 | 39.04% |
| BRAM36 等效 | 32 / 50 | 64.00% |
| DSP | 4 / 90 | 4.44% |

相较上一份四路 10 位 UART 诊断实现（11,500 LUT / 13,962 FF / 32 BRAM36 / 4 DSP），本配置增加 1,446 LUT 和 2,278 FF，BRAM 与 DSP 数量不变。这是两次实际实现报告的差值，包含物理优化差异。此次布局配置没有上电波形；包含上电波形、100 MHz 差分输入和 1M 串口的 USB 工程另外通过生成与仿真检查，未对该组合重复布局布线。

8 个 USB 总线方向寄存器均实际放置在 IOB 的 TFF；4 项 Gray 指针 bus-skew 检查通过，最小裕量 +4.279 ns。CDC 报告仍有 2 项复位组合路径告警，对应异步置位、三级同步释放的复位链，需保留人工审查记录；不能称为所有 CDC 告警清零。DRC 没有错误，4 项告警为扫描端点 DSP 输入流水建议。具体资源、报告与源码关联见 [验证摘要](validation/usb_uart/summary.json)。

本次检查没有 DAC 外部采样边沿、建立 / 保持时间及板级输出延迟，因此仅完成内部核心和已约束 USB 数字接口检查，**没有完整系统时序签核，也没有生成本轮 BIT**。本机未枚举到 FT232H 数据接口，尚未测试真实 USB 下载速度、线缆、驱动和模拟 DAC 电压。软件选择 USB 与真实设备可用是两件独立的事。

以上是 9 月 16 日开发阶段的记录，后续实际烧写、延迟假设和 USB 测量见本文开头的 9 月 17 日记录。更新 EXE 不会更新 FPGA；其他板卡首次使用 USB 仍需要匹配的固件。普通 USB / UART 波形下载不写 Flash。

最终 EXE 已通过三组便携检查：中文 / 空格路径离屏自检、移动目录后的 Windows Qt 自检，以及通过打包程序调用真实 Vivado 生成含 USB、1M UART、100 MHz 差分参考和 BRAM 上电快照的工程。生成工程的 USB / UART / 波形 RTL 与时序脚本逐字节匹配本次源码。检查记录见 [EXE 验证](validation/usb_uart/executable_validation.json)，源码与报告的对应关系见验证摘要；后续改动源码或配置后应重新验证。
