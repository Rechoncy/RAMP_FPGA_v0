# UART 自动波特率

同一份新版 FPGA 固件支持 **9600、19200、38400、57600、115200、230400、460800、921600、1,000,000 baud**，格式为 8N1。不需要为每档速度分别生成、烧录 BIT。

**R2 已完成 CH340 实板验证：**最初的 R1 识别器未考虑高速串口的字节间空闲，主机低速训练还需要等待 UART FIFO 排空。两项均已修复，九档切换、四路播放期间重连、每路 2048 段下载通过，3549 次命令交换无重试。使用 `release/FPGA-XC7A35T-AutoBaud-20260917-R2/125MSPS/ramp_studio.bit` 和新版 EXE；本轮已临时 JTAG 下载，未写 Flash。过程与原始记录见 [UART 实板验证](UART实板验证_2026-09-17.md)。

## 使用方法

1. 旧固定波特率固件先升级一次。仅更新 EXE 不会升级 FPGA。
2. 使用新版 Ramp Studio，等待当前通信操作完成，再断开串口。
3. 在“板卡与连接”的波特率选项选择速率，然后连接。
4. 软件完成同步及 INFO 读取后，设备摘要显示“波特率自动适配”。之后下载波形和控制操作沿用原流程。

“板卡信息 → UART 上电默认波特率”对应板卡 JSON 原有 `uart_baud` 字段。默认保持 115200 即可；它仅决定复位后的初始速率，连接训练可以切换到任一支持档位。电脑所选速率随正常退出保存，FPGA 每次重新上电先使用默认值，再由软件连接时训练。需要掉电仍使用新版本固件时，固化一次新版本 Flash；不必为每种速率重写 Flash。

现有波形、初始码、中止码、布防和运行状态不会因串口同步被清空。正在播放的波形按原时序继续，切换通信速度不会调整 DAC 时钟。USB FIFO 不使用波特率，也不发送串口训练；同一固件继续支持 USB FIFO 与 UART，软件一次选择一个入口。

## 同步协议与固件能力

协议帧仍是原来的 32 字节、CRC16、序号与命令结构，没有增加可能改变 DAC 状态的设置命令。

| 步骤 | 主机行为 | FPGA 行为 |
|---|---|---|
| 打开串口 | 按所选速率设置 8N1 | 尚未训练时仍可用上电默认速率通信 |
| BREAK | TX 拉低至少 20 ms | 检测到连续低电平达到 10 ms 后，仅暂停 UART 接收并清空半包 |
| 训练 | 发送 16 个 `0x55`，等待发送完成 | 累计 24 个有效位间隔；允许完整训练字节之后的长高电平空闲，空闲本身不计数 |
| 锁定 | flush 后等待 `16 × 12 / baud + max(0.01, 24 / baud)` 秒，覆盖训练串排空及空闲 | 线路空闲至少 12 个候选位时间，且 UART 发包完全结束后更新分频 |
| 确认 | 清空接收缓存，发送正常 INFO | 按新速率回复，CRC 与序号校验保持原样 |

INFO **24 字节 payload 的索引 19、bit 4（0x10）** 是 `UART_AUTOBAUD` 能力标志。对应完整 32 字节帧的索引 25。其余能力位和原有命令不变；上位机将该位解析为 `Capabilities.uart_autobaud`。Xilinx 单端、差分及 USB+UART 生成顶层启用该标志；单独复用旧控制器模块时，该参数默认关闭，集成者应按实际链路能力设置。

FPGA 使用两级同步、间隔识别与分频器。只接受九档标称值，识别窗口为标称分频的 ±2% 加一个核心时钟周期；该窗口是识别容差，不等于承诺 UART 在任意 ±2% 总误差下均可可靠通信。R2 在已累计九个稳定间隔之后，允许至少 1.5 倍标称位时间的高电平空闲跨过字节边界；不足一个完整字节的碎片、异常低电平和速率改变仍会清空累计。收发分频只在空闲边界更新，不切换全局时钟，不复位波形控制器。

未发送 BREAK 的普通数据不会触发重新识别。训练未完成或非法间隔无法锁定时，自 BREAK 释放后约 250 ms 超时恢复原速率。错误 CRC 不执行命令。旧固定速率固件忽略训练序列，但只能在原固定速率下回复，因此界面会显示“旧固件固定波特率”。自编主机可以调用 `SerialTransport.synchronize()`；常规 `Device` 建立连接时自动调用一次，普通查询和下载不重复训练。

## 使用边界

1M 表示 1,000,000 baud；8N1 的单向数据上限约 100,000 字节/秒，实际波形下载还受帧头、应答和软件开销影响。USB-UART 芯片、驱动以及实际线路必须支持所选速率；出错时可断开并改用较低档位重连，无需改烧其他波特率固件。

本轮 R2 经用户授权临时 JTAG 下载并完成当前 CH340 链路的数字检查，未改写 Flash；掉电后恢复 Flash 原有版本。没有进行 DAC 模拟电压或物理逐拍测量，也不将当前链路的通过推广到所有适配器。完整资源、700 项回归和便携 EXE 验证见上述实板报告。以下 R1 记录仅供历史追溯。

## R1 离线验收记录

2026-09-17 的最终检查共 **688 项通过、1 项跳过**：682 项项目回归，加 6 项自动波特率 RTL 检查。跳过项为 Windows 无原生符号链接创建权限；其他路径保护和 NTFS junction 检查已执行。自动波特率测试覆盖：

- 同一实例连续切换九档速率，100 / 125 / 200 MHz 核心均通过；对端独立时基为标称周期 ±0.8%，请求与完整回复均校验 CRC。
- 默认速率旧主机无需训练仍能连接；新版训练字节可被旧固定波特率接收器忽略。
- 无 BREAK、短 BREAK、训练不足、非法间隔、间断噪声不切换分频；超时恢复旧值，TX 忙时不切换，复位恢复上电默认值。
- 真实波形控制器以 100 MHz 持续播放，默认速率改为 1M 的全过程逐拍核对输出，没有丢拍、重复拍或重置波形。
- 上位机训练在 INFO 前只执行一次，短写失败关闭连接，旧/新能力位正确识别。便携 EXE 在含中文和空格的迁移路径、无 Python/Qt PATH 环境下通过 offscreen 与 Windows 两组完整启动检查，另确认 x64 GUI 和内嵌图标。
