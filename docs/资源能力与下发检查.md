# 资源能力与波形下发检查

软件连接设备时读取 FPGA 固件的能力回报，并在准备或下载前再次核对。界面显示当前方案需要的容量、设备允许的上限和检查结果；超限或不兼容的方案会阻止下发。

## 在哪里查看

| 位置 | 显示内容 |
|---|---|
| 板卡与连接 | 当前能力来源、DAC 数量与位数、每路码段容量、事件步骤容量；“刷新能力”重新读取连接设备 |
| 方案设计与保存 | 编辑后的完整离散与容量检查结果；检查完成前显示等待或检查中 |
| DAC 单路页面 | 分配给该 DAC 的本地保存方案需要多少容量，是否符合当前设备能力 |
| 输出总览 | 各路已分配方案的检查状态，便于在“准备所选”前发现超限通道 |

这些结果检查的是**即将准备的本地方案**。修改本地方案或更换分配不会自动更改已经加载的波形；设备上的活动版本仍以状态回读和已确认加载记录为准。

## 分清能力来源

- **已连接实板**：以固件 GET_INFO 回报为准。修改软件中的 FPGA 型号、DAC 数量或位数，不会修改板上已烧录的能力。
- **未连接**：按当前板卡配置和默认固件规则预估，不能作为实板已通过的结论。连接后会用设备回报重新检查。
- **演示设备**：使用模拟能力，可验证软件操作流程，不代表检测到了真实 FPGA。

“刷新能力”只读取当前连接固件的信息，不重新烧写 FPGA，也不下载波形。已有支持 GET_INFO 的固件可以直接使用容量检查；个别波形功能仍需固件提供对应能力，例如无限重复、触发步进和事件序列。

## 容量为什么用“码段”表示

波形仍按 **200 MHz，即每 5 ns 一个采样点** 完整计算、取整。相邻采样点的整数原码相同时，软件把它们保存为“原码＋持续周期数”的一个连续码段，执行时按原时钟保持对应原码，不降低采样率。

例如，恒定原码保持 100 ms，包含 2000 万个时钟周期，却只需要一个码段。快速振荡波形可能每拍改变原码，在很短时间内就用完容量。因此，波形总时长、预览图的绘制点数都不能直接代表需要多少存储槽位。

当前默认独立多路固件分配如下：

| 固件中的 DAC 数量 | 每路可容纳的连续码段 |
|---:|---:|
| 1 | 8192 |
| 2 | 4096 |
| 3～4 | 2048 |
| 5～8 | 1024 |

**连接后以设备实际回报为准。** 这是固件预先为各路分配的容量：DAC 2 没有加载方案，也不能把它的空闲槽位借给 DAC 1。仅取消某路参与输出不会扩大其他通道的容量。

固件还设有活动和待提交两个存储 bank，确保完整下载后才切换配置。界面显示的是一份方案能使用的容量，不能把两个 bank 相加。例如四路默认固件的单路上限仍为 2048，而不是 4096。

## 不同模块检查什么

| 模块 | 容量与兼容性检查 |
|---|---|
| Ramp、固定时长自定义函数 | 一轮完整离散后实际连续码段数，以及位数、原码和触发配置；选择无限循环时额外检查无限重复能力 |
| 电平门控 | 进入段与返回段合计码段数；外部高电平的未知保持时长不展开为采样表 |
| 固定时间表 | 包含时间间隔和步骤重复后，整张时间表的最终码段数 |
| 事件／门控步骤 | 本 DAC 波形池码段数及事件步骤数；当前固件最多 64 步，相同波形数据可在同一通道的步骤之间复用 |
| 触发步进 | 固件是否支持、点数 1～65535、起点、步长和末点范围；只下载配置参数，不逐点写入波形码段 |
| 旧版分段方案 | 旧分段容量与固件兼容性；独立多路固件不直接支持历史双输出分段／FM 协议 |

触发步进的 65535 点是当前协议规定的上限，不是从波形 RAM 推导出来的。它不使用采样表，但相关硬件逻辑及波形 RAM 仍已包含在固件中，因此不能理解成扫描模式让 FPGA 的物理 BRAM 占用归零。

固定时长 Ramp、自定义函数和固定时间表的无限循环都复用一轮数据，不按循环次数扩展码段。单波形仍须通过完整离散和每路容量检查，不能因选择无限循环而跳过这些限制。未连接时可保存无限方案；连接后的准备或下载会检查 `infinite_repeat` 能力，不支持时在波形写入前拒绝下发。已支持该能力的固件无需仅为增加界面选项重烧。

主机也有自己的编译边界，例如单次函数最多计算 2 亿个采样点、当前采样编译器最多生成 8192 个码段。超过这些边界会显示编译限制；即使未超过，仍需继续满足连接设备的每路容量。函数原码越界、无定义采样值或位数不匹配也会阻止下发。

## 准备和下载时的流程

1. 读取当前连接设备的最新能力。
2. 对本次所选 DAC 的本地保存方案完整编译，检查功能、位数、触发、码段数和事件步骤数。
3. 任一路不通过，停止本次准备，不向所选 DAC 写入新波形。
4. 全部通过后，沿用版本匹配规则，下载需要更新的通道；已确认匹配的配置可以复用。
5. 回读确认后布防。后续播放和外部触发仍由 FPGA 执行。

编辑参数后，上一次检查结果会失效；必须等待新结果。预览只取部分位置显示，不能替代完整离散检查。离线通过也不能代替连接后的能力复核。

多路准备会先统一检查，再逐路完成配置提交。各通道有自己的双 bank；这不等同于所有通道在同一时钟同时切换新配置。同步开始输出仍通过准备完成后的分组布防或触发完成。

## 超限后如何调整

例如 `2,401 / 2,048 码段` 表示超过该 DAC 容量 353 个码段，应先调整波形，再等待重新检查。

- 对反复振荡的函数，适当减少周期数、降低变化频率或缩短需要播放的时间。
- 对事件序列，复用同一波形快照，检查是否存在不必要的不同波形副本。
- 若实验允许，拆为不同时间执行的独立方案；分别准备会改变使用方式，不能代替原来要求连续输出的完整波形。
- 确实需要更大单路容量时，调整固件的存储分配，重新构建并检查资源与时序后再烧写。只修改上位机显示的 DAC 数量不会增加实板容量。

软件不会为使波形“通过”而自动降采样、截断、缩放原码或减少步骤。

## 能否自动得到整颗 FPGA 的 LUT、FF 和 BRAM 总量

当前串口能力回报提供的是**板上固件向波形播放开放的能力**，不含芯片型号、LUT、FF、DSP 或物理 BRAM 的实时占用。协议中的平台 ID 只是固件类别，也不能用来识别具体 FPGA。

左侧栏底部的「硬件资源」常驻显示 LUT、FF、BRAM、DSP 占用百分比；点击后可在完整报告窗口查看已用 / 总量与来源。软件自动读取本机构建报告，也可在该窗口点击「导入报告」选择 Vivado `utilization.rpt`；没有本机构建记录且器件匹配时，提供明确标注的发布固件参考。来源、生成阶段、时间与配置关联说明见[板卡硬件资源占用](板卡硬件资源占用.md)。

已有报告只对应它所构建的型号、参数和镜像，不能当作任意连接设备的实时结果。波形下载是在已分配内存中写数据，不会重新综合逻辑，因而日常下发主要需要检查每路码段容量及功能限制。

配置和波形掉电保存方式保持原有行为，见[软件详细使用手册](软件详细使用手册.md)；通信字段见[协议 v1](协议-v1.md)。
