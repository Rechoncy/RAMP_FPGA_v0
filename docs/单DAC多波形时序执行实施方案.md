# 单 DAC 多波形时序执行实施方案

整理日期：2026-09-12。本文保留原实施设计；软件与 RTL 后续已按本方案扩展，实际入口和规则以 [执行序列使用说明](执行序列使用说明.md) 为准，具体测试/烧录范围见对应验收记录。

## 1. 需求与推荐路线

一个 DAC 可以在不同时间输出多个波形。应新增“执行序列”，使现有保存波形成为可复用的序列步骤：

```text
波形库：Ramp A、三段高斯 B、Ramp C……
执行序列：开始条件 + 波形引用 + 时间/等待条件 + 重复 + 结束行为
DAC 1：选择并下载一个执行序列
DAC 2～4：各自选择单波形或执行序列
```

Python 负责编辑、完整离散、原码取整、容量检查及提前下载。FPGA 负责到时切换和触发响应。默认时间基准是某次已接受的触发事件，不是电脑的日历时间。

优先实施“固定时间表”：一次触发后，DAC 按表播放多个已知时长的波形。它可以复用现有 FPGA 码段播放器，先交付上位机改动。再按需求增加硬件序列器，支持“每次触发推进一个波形”、步骤间等待外部事件和门控波形。

## 2. 当前程序能力与限制

核对依据：`host/model.py`、`host/parallel_page.py`、`host/protocol.py`、`host/boot.py`、`rtl/common/controller.v`、`sample_engine.v`、`parallel_controller.v`。

- 方案库可保存多个 `Profile`，但每路 DAC 当前只分配一个保存方案。
- 每路控制器只有一份活动波形参数；另一 bank 是下载事务的缓冲。双 bank 不等同于两个可独立选择的波形槽。
- 现有播放器可逐拍播放多个 `(原码, 持续拍数)` 描述符。因此，预先拼好的多个波形和等待段，在硬件看来可以是一条长波形。
- 当前四路配置每路每 bank 最多 2048 个码段。多波形拼接后共同占用这 2048 段，不是每个波形各有 2048 段。
- 目前上传 API、方案模型、预览、保存指纹和上电快照都围绕单 `Profile` 实现。即使第一阶段不改 RTL，也必须修改这些主机路径，不能只加一个列表框。
- 当前串口为 115200 / 8N1，固定 32 字节请求/应答。按 2048 个码段逐条传输，仅写段请求与应答的线速时间就约为 `2048 × 64 × 10 / 115200 = 11.38 s`，尚未包括其他命令和软件开销。不能在预定输出前临时下载下一波形来保证精确切换。

## 3. 三种执行方式

| 方式 | 用户设置 | 典型用途 | 实现 |
|---|---|---|---|
| 固定时间表，优先 | 相对一次起始触发的开始时间 | 触发后依次执行多种脉冲 | 主机展开为连续码段，复用现有播放器 |
| 顺序事件 | 当前步骤等待指定输入的新边沿，播放完再进入下一步 | 第一次有效触发播放 A，下一次有效触发播放 B | 新 FPGA 序列器、波形目录和步骤表 |
| 门控步骤 | 上升沿进入、高电平保持、下降沿返回；返回后推进 | 外部实验事件决定每个波形的保持时长 | 新序列器协调现有门控引擎 |

“来第几个触发就用第几个波形”依赖预先约定的顺序。如果希望任意指定 A/B/C，单根外部输入的相同边沿不能携带波形编号，需要另加预选命令、输入映射或专门的编码接口。第一阶段不引入这种随机选择协议。

固定时间表也可选择“上一波形结束后等待 X 再开始”，但保存和编译时必须换算成唯一的时间表；不要让“间隔”同时表示开始到开始、结束到开始两种含义。

## 4. 操作示例和时间规则

DAC1 的序列“实验流程 01”，共同初始/结束码 512、中止码 512，外部输入 1 上升沿启动：

| 步骤 | 开始时间，相对触发后序列起点 | 波形 | 单次时长 | 结束时间 |
|---|---:|---|---:|---:|
| 1 | 0 ms | Ramp A：70 / 100 / 70 ms | 240 ms | 240 ms |
| 2 | 300 ms | 三段高斯 B：10 / 20 / 10 ms | 40 ms | 340 ms |
| 3 | 500 ms | Ramp C：30 / 60 / 30 ms | 120 ms | 620 ms |

其中 240～300 ms、340～500 ms 持续输出 512。620 ms 后保持 512；可选结束或等待下一次外部触发后从步骤 1 重放。

时间精度规则：

1. 使用 200 MHz 核心的整数拍数，1 拍为 5 ns。UI 继续支持 ns/µs/ms/s，并同时显示请求值和量化后的实际值。
2. 保存开始时间和时长的明确单位；编译成整数 ticks 后进行排序、重叠检查及加减运算。绝对偏移分别从共同起点量化，避免多次浮点累加带来的误差。
3. 每个步骤占用半开区间 `[start_tick, end_tick)`，相邻步骤可在同一边界交接。量化后不能重叠，不允许两个波形同时占用同一个 DAC；不同 DAC 可以重叠。
4. 原波形每段的端点和采样规则保持现状，不为每个内部波形偷偷增加一个“返回初始值”的采样拍。下一步骤或等待段按其起始拍接续。
5. 5 ns 是数字时间网格，不等于外部触发到模拟电压的总延迟或测量精度。外部同步、输出寄存器及 DAC 延迟另行计入并实测。表中的序列起点统一指播放路径的第一输出采样拍。

输出码衔接规则：

- 第一阶段要求同一序列的波形使用相同初始/结束码。序列设置统一的等待码和中止码，避免某个步骤覆盖全序列的停止行为。
- 若相邻波形需要不同初始码，第一阶段提示用户修改；后续可增加显式“静态切换”或“过渡斜坡”步骤，并计入时长和容量。不能自动插入用户未设置的变化。
- 步骤内重复次数与整个序列的重复次数分别显示。时间表计算必须包含步骤重复，不能隐藏地继承模板中的循环和触发设置。
- 原波形的触发输入/边沿由序列统一控制；引用时只复用形状参数。界面显示这种覆盖关系。门控波形必须走门控步骤，不能当作已知总时长波形插入固定表。

## 5. 界面及保存结构

保持蓝白风格和当前左侧 DAC1～4 的结构，在“方案设计与保存”内增加两个页签：

| 位置 | 改动 |
|---|---|
| 波形库 | 保留 Ramp、三段函数、原码、初始值和时长编辑，保存单个波形模板 |
| 执行序列 | 新建、命名、复制、归档、导入/导出序列；从波形库添加步骤 |
| 序列表格 | 启用、顺序、波形名称、开始方式、开始时间/等待时长、次数、实际结束时间 |
| 时间轴预览 | 单路整条曲线与每个波形边界；点击步骤定位；标记等待段、冲突及量化结果 |
| DAC1～4 | “使用内容”选择单波形或执行序列；显示版本、总时长、容量、当前步骤/等待条件 |
| 多路同步 | 各路仍独立分配；统一起始触发下可有不同时间表，共用时间起点 |
| Flash 固化与启动 | 纳入所选序列及其全部引用波形的保存快照 |

建议新增 `user_data/sequences/`，序列包含 UUID、schema、名称、位数、统一初始/中止码、启动方式、结束策略和 steps。方案库 ID 与保存版本/内容哈希一起记录，导出时嵌入波形快照。重新编辑波形库不会静默改变已经保存或下载的实验序列；用户通过“更新引用到当前保存版本”明确更新。

通道分配采用带类型的引用，例如 `kind=profile/sequence` 和 `id`。旧 `parallel.json` 单波形记录自动迁移为 `kind=profile`，不改用户的输出内容。当前下载身份核验需同时比较序列、步骤参数及所有波形快照。

## 6. 第一阶段：固定时间表，复用现有 FPGA

### 编译与传输

新增 `Sequence`、`SequenceStep` 和 `CompiledSequence` 模型，流程如下：

```text
冻结所引用的保存波形
  → 校验位数、初始码、时长及重复
  → 计算量化后的每一步时间区间
  → 每个波形按 200 MHz 完整离散和取整
  → 插入指定原码的等待码段
  → 拼接并无损合并相邻同码段
  → 检查总容量、每段计数和整体结束策略
  → BEGIN_RUNS / WRITE_RUN / COMMIT 一次提交
  → ARM 后按一个完整序列播放
```

同一波形重复使用时，第一阶段可以复用主机编译缓存，但展开后的每次非连续重复仍占用 FPGA 码段空间。顶层整个序列重复可使用现有 repeat。第二阶段再通过波形地址引用消除多次出现的数据副本。

不要先建立整个实验长度的 NumPy 数组；波形按块编译，等待直接生成码段。同一码段拍数不得超过现有 32 位无符号计数上限，长等待拆为多个合法码段。单段上限约 21.47 s；整体时间计算使用主机整数和显式上限，不能因计数溢出绕回。每个函数仍执行现有 1 s 离散限制；序列总时长需另设容量/处理限制，不能用现有单 Profile 总时长校验直接套用，也不能无提示放宽原函数计算上限。

复用协议外壳与现有播放硬件，但需要在 `host/protocol.py` 增加接收已验证编译结果的上传入口。此入口重新检查设备实际位数、容量、计数范围和通道状态，不能以“预编译”为由绕过校验。

### 状态与兼容性

- 旧四路固件可以把整表当作一个波形执行；不需要为每个步骤重烧 FPGA。
- 使用支持自动布防的固件时，可以在整表完成后等待下一次外部事件。旧板上固件 `09112040` 没有该新增能力，仍需整表结束后手动 ARM；不能仅更新 EXE 就声称已有自动重放。
- 现有 `run_index` 和主机保存的码段映射可用于近似显示当前步骤；连续同码段可能跨过步骤边界，且串口没有逐拍时间戳，界面不能据此声称精确知道每个 5 ns 的步骤位置。需要准确事件历史时使用第二阶段的步骤状态与硬件计时回报。
- `host/boot.py` 扩展为编译单波形或完整固定序列，继续把码段及全局配置放入原格式 RAM 初始化镜像；不需要为固定表另加实时调度 RTL。但永久修改必须重新生成并固化对应 `.bit`。

第一阶段不支持：每一步等不同外部边沿、未知高电平时长后的绝对时间安排、运行中任意跳步、多个驻留波形随机选择。

## 7. 第二阶段：波形目录与 FPGA 序列器

### 内部结构

每路 DAC 增加三类数据：

1. **波形目录**：波形 ID、码段池起始地址/长度、固定或门控模式、初始/目标等形状参数。
2. **步骤表**：波形 ID、等待方式、延时拍数、触发输入/边沿、步骤重复及下一步。第一版限制为顺序执行和整表循环，不实现任意条件跳转。
3. **序列器**：维护当前步骤、等待条件、循环次数、错误原因，并驱动固定/门控播放引擎。

```text
未就绪 → 预取 → 等待起始条件 → 播放当前步骤
                                   ↓
                步骤完成 → 等待延时/新边沿 → 播放下一步骤
                                   ↓
                最后步骤完成 → DONE 或从步骤 1 重新等待
任意执行状态 ──中止──→ 统一中止码，取消后续步骤
```

建议首版设计目标为每路最多 16 个波形目录项、64 个执行步骤，保持 4 路独立及 10/12/14 位参数化。这是待综合验证的上限，最终通过扩展 INFO 返回实际能力。多个波形共同使用每路码段池，不把“16 个槽”解释为存储容量扩大 16 倍。

保存一份波形数据后，可被多步骤引用；例如 A→B→A 只保存 A 和 B 两套数据。这解决第一阶段重复展开浪费容量的问题。保持活动/待提交两套完整目录、步骤和码段的一致性，以整个序列为原子单位 COMMIT；第一版继续禁止运行中或已布防时修改该通道。

### 预取和 200 MHz 时序

固定时长的后续步骤在边界前预取目录与首批码段，不能到结束时再依次发送 ARM/查询存储。7 系列 BRAM 具有具体读写模式与同地址冲突规则；新增目录、缓存和 bank 切换要显式设计时序及所有权。[AMD UG473](https://docs.amd.com/v/u/en-US/ug473_7Series_Memory_Resources)。

既定固定时间表目标是无额外空拍衔接。外部事件步骤只有在下一步准备就绪后接受新边沿，预取完成前的边沿不排队，并返回“未就绪”状态。实现并仿真确认所需准备周期，文档再填写最小可接受触发间隔。不能把未知转移延迟包装为已有的 5 ns 切换保证。

当前上电波形实现的核心 WNS 记录仅 +0.008 ns，新增逻辑后必须重新完成 200 MHz 时序收敛；不以剩余 LUT/BRAM 数量代替时序验证。四路可按共同触发开始，物理管脚偏差仍须实测。

### 外部事件和门控的确定规则

- 第一次已接受触发执行 A，A 完成且 B 预取就绪后，下一次新触发执行 B；不能把忙时被忽略的边沿算成序列推进。
- 第一版忙时边沿忽略并计数，不打断、不排队。每次序列 ARM 从步骤 1 开始；保留继续当前步骤作为后续显式功能。
- 门控当前步骤内部：上升进入、高电平保持、下降返回，返回完成才推进。门控引擎完成后应交回序列器，而不是沿用自身自动重布防去重复当前波形。
- 门控结束时间未知，后续步骤使用“上一段结束后延时/等待事件”。不与固定绝对时刻混排；若今后支持混排，必须增加超时/错过截止时刻的明确策略。
- 序列等待时保持配置的等待码；中止使用通道统一中止码，并禁止自动重新启动。改变序列引用、断连或打开其他页面不会自动发出输出命令。

### 协议与上电恢复

增加能力查询和序列命令。可在尚未使用的命令范围内分配 `GET_SEQUENCE_INFO`、`BEGIN_SEQUENCE`、`WRITE_WAVE_META`、`WRITE_STEP`、`COMMIT_SEQUENCE`、`GET_SEQUENCE_STATUS`；正式编码时检查冲突并更新协议文档。沿用固定帧 CRC、序号、精确重试和错误码语义，不能改写旧命令使旧程序误解析。

状态返回当前序列 ID、步骤、等待原因、prepared、步骤/整表完成次数、忽略事件数与错误。事务失败保持旧活动序列，ACK 超时仍视为结果未知，随后读取身份核对。

Flash 快照升级为整个“波形池 + 目录 + 步骤表 + 通道配置”。完整上电从步骤 1 等待起始条件；不默认恢复掉电瞬间的中间步骤。运行中逻辑复位与完整重配置继续区别处理，避免已被 UART 改写的数据配上旧启动元信息。

## 8. 实施顺序与验收

| 交付阶段 | 主要改动 | 验收条件 |
|---|---|---|
| A：模型与固定表编译 | 新增序列模型/编译器、整数时间、快照和冲突检查 | 示例时间区间正确；原码不缩放；越界、重叠和容量超限明确报错 |
| B：界面与现有设备兼容 | 序列页、时间轴、DAC 类型选择、编译上传、演示器 | 保存/重开/导出一致；一次下载后 A→等待→B→等待→C 完整播放；其他路不受影响 |
| C：固定表掉电快照 | 扩展 boot 生成及身份核验、更新 EXE/手册 | 生成镜像与普通下载的码段逐项一致；实板固化并完整断电后，无波形重传可执行 |
| D：事件序列 RTL/协议 | 目录、步骤表、预取、事件调度、状态与仿真 | 外部触发正确推进；门控完成正确推进；无边界丢拍；错误事务不替换活动配置 |
| E：实现与实板 | 200 MHz 实现、器件资源检查、JTAG/UART/Flash 验证 | 时序通过；仪器测量步骤边界和触发响应；四路并发及停止隔离；新版完整冷启动 |

关键验证矩阵：10/12/14 位；单拍/长码段；零间隙/有间隙；重复波形；步骤重复/整表重复；首尾码；满容量/超容量；量化后重叠；晚到/忙时触发；门控提前下降；取消/中止；断连保留；上电快照被临时上传替换后复位保护；旧方案迁移。

第一阶段必须用逐拍数字仿真核对拼接后的整个码流，而不只观察 GUI 动画。最终物理时间与模拟输出由逻辑分析仪/示波器验收，串口状态轮询不能证明纳秒边界。

## 9. 本次建议

先把界面和保存模型统一为“波形库 + 执行序列”，交付固定时间表编译方式。这样，提前确定的多个波形可以一次下载后由现有 FPGA 自主定时输出，日常修改不需要重烧硬件。

如实验需要“每次外部触发换下一个波形”或门控决定步骤长度，再实施第二阶段硬件序列器；它复用相同的序列编辑界面与快照格式。是否支持某种序列在下载前依据设备能力明确判定，不在连接旧固件时退化成电脑定时切换。

以上是最初设计时的阶段划分。后续已实现固定时间表、事件/门控序列及共用/独立输入路由；最终保存格式、协议和操作方式以《执行序列使用说明》为准。实板烧写与冷启动验证需查看对应版本验收记录，不能由本方案的验收目标推定已经完成。
