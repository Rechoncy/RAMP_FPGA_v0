# Debug · 静态 DAC 输出

1. 在左侧“板卡与连接”中选择并连接设备，或先连接“演示设备”。
2. 打开左侧 **Debug 静态输出**。
3. 选择输出 DAC，输入静态原码和本次提交的中止码。
4. 点击 **应用静态输出**，核对“设备回读”的通道和原码，再用仪器测量实际输出电压。

支持当前设备的 10/12/14 位范围，分别为 0～1023、0～4095、0～16383。通道数量取连接设备的实际能力；修改板卡配置不会改变已连接设备的位数或数量。位数减小时保留输入的原码并标记越界，不自动缩放。

“填入最小码 / 数字中点 / 最大码”只修改输入框，不发送。“返回方案初始码”和“输出数字中点”会立即向所选通道提交新的静态配置；中止按钮使用已经提交到设备中的中止码，未应用的输入值不会改变中止行为。

独立多路固件中，一次提交一个 DAC 的静态值，其他 DAC 保持原配置，可分别设置后同时输出不同静态值。旧单播放器固件中其余 DAC 为数字中点（512/2048/8192）。静态值不需要触发，DAC 时钟继续为 200 MHz；切换页面或断开串口后硬件仍保持输出，直到新配置、中止命令或硬件复位改变它。输出回报码不是模拟电压测量。原有 10 位 DAC 的码值 0 对应最大正电压，不能当作零电压。

运行中或等待触发时不能直接应用静态配置。先中止，或在等待触发状态取消布防。静态配置会替换设备中当前下载的波形；回到对应 DAC 页面后需要重新下载方案才能布防。本地已保存和正在编辑的方案不会被静态操作改写。

本功能使用现有 BEGIN_RUNS / RUN / COMMIT 提交恒定初始码，并保持未布防状态，不发送 ARM/TRIGGER，不需要为此更新支持 200 MHz 函数播放的固件。界面在提交后校验状态、配置 ID、通道和原码；命令超时或回读不一致会显示未确认，不宣称实际输出已经成功。请求、确认和错误均记录在 `user_data/logs`。

返回初始码现在使用 Debug 所选 DAC 在通道页分配的**已保存方案**，不读取设计页草稿。该 DAC 未选择方案时禁用此按钮。静态输出后，回到对应 DAC 页面重新下载所选方案，再布防。
