# Ramp Studio 协议 v1

本文对应已实现代码，取代早期方案文档中的可变长度帧草案。数值为小端；串口默认 115200 baud、8N1，单请求/单应答。可选 FT232H USB FIFO 使用同一帧结构，批量上传允许有界窗口，控制器仍按序完成每条事务。软件一次选择一个物理接口连接。

## 串口速率

电脑端连接设置和板卡构建参数均可选 9600、19200、38400、57600、115200、230400、460800、921600、1,000,000 baud。电脑端仅在断开时可修改；FPGA 端由“固件 UART 波特率”在生成工程时确定，改变后须重新实现并烧录。该设置适用于单端 / 差分参考时钟与包含上电方案的固件，未填写的新字段按 115200 处理。

本协议不通过运行时命令协商或切换波特率，双方必须事先使用匹配速率，才能交换 GET_INFO 等帧。修改波特率不改变协议版本、固定帧长度、CRC 或命令含义。现有发布参考 BIT 仍使用 115200；保存板卡 JSON 或只改上位机连接值不会更新板上逻辑。要在完整从 Flash 启动后使用新速率，须固化对应固件。

在 200 MHz 核心下，1,000,000 baud 对应每位 200 个核心周期；修改 UART 波特率不改变 200 MHz DAC 播放时钟。1M 是每秒 1,000,000 波特；8N1 的单向字节线速上限为 100,000 字节/秒，实际下载须再计入 32 字节请求、32 字节应答以及等待开销。USB-UART、驱动和接线仍需验证目标速率；pySerial 将 1,000,000 列为许多平台 / 设备可用的高速值，不保证全部适配器支持。[pySerial 官方 API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html#serial.Serial)

## 帧结构

固定 32 字节：

| 偏移 | 长度 | 内容 |
|---|---:|---|
| 0 | 2 | A5 5A |
| 2 | 1 | 版本 01 |
| 3 | 1 | 命令 |
| 4 | 2 | 请求序号 u16 |
| 6 | 24 | 负载，未使用字节置零 |
| 30 | 2 | CRC-16/CCITT-FALSE，小端 |

CRC 初值 FFFF，多项式 1021，不反射，不做最终异或；覆盖偏移 2–29。`123456789` 的 CRC 为 29B1。

应答命令为请求命令 OR 80h，序号原样返回。应答负载第 0 字节为错误码：0 成功、1 不支持、2 状态不允许、3 参数错误、4 配置不完整。

设备缓存最近一条完整请求和应答，精确重复的请求只返回缓存，不重复执行副作用。双接口固件同时比较内部请求来源，避免 USB / UART 相同序号的不同事务误命中；该来源标记不改变线上帧或 CRC。主机单帧超时重发必须使用相同帧，不能换序号。串口超时最多重发两次；最终超时表示结果未知，应读取状态或重新连接。USB 批量窗口失败不自动整窗重发，见文末批量扩展。通道选择与待提交波形是共享状态，不支持两个客户端并发控制。

## 命令

### 01 GET_INFO

请求无负载。应答负载：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | 错误码 |
| 1 | u32 | 核心 Hz，目前 200000000 |
| 5 | u16 | 旧分段执行器最小更新分频，目前 16；新采样播放器固定 1 拍 |
| 7 | u16 | 最多段数，目前 64 |
| 9 | u8 | DAC 位数：10、12 或 14；由构建参数 DAC_BITS 决定，同一设备统一位数 |
| 10 | u8 | DAC 时钟分频，目前 1，即 200 MHz；旧固件为 4，即 50 MHz |
| 11 | u16 | 固件平台 ID：单播放器版本为 1，独立多路版本为 2 |
| 13 | u16 | 采样模式每通道每 bank 最大连续码段数，按设备回报；四路配置为 2048，单路配置为 8192；旧固件返回 0 表示不支持 |
| 15 | u8 | DAC 通道数，1～8；旧设备为 0 时主机兼容为 2 |
| 16 | u8 | 触发输入数，1～8；旧设备为 0 时主机兼容为 2 |
| 17 | u8 | 能力位：bit0 触发路由/边沿，bit1 电平门控，bit2 独立多路，bit3 固定时长外部自动布防，bit4 上电波形，bit5 事件序列，bit6 无限重复，bit7 触发步进；当前多路值 239，包含上电方案时为 255 |
| 18 | u8 | 事件序列最多步骤数，需 bit5；当前为 64 |
| 19 | u8 | 扩展能力：bit0 分段线性插值，bit1 RUN_BATCH，bit2 USB FIFO；本版其余位为 0 |
| 20 | u8 | 最短插值段拍数，需 byte19 bit0；当前为 32 |
| 21 | u8 | 插值语义修订号，需 byte19 bit0；当前为 1 |
| 22 | u8 | 批量上传语义修订号，需 byte19 bit1；当前为 1 |
| 23 | u8 | 每个 RUN_BATCH 最多段数，需 byte19 bit1；当前为 3 |

GET_INFO 回报的是固件能力，不是 FPGA 芯片型号或物理 LUT/FF/BRAM 总量。平台 ID 不用于识别具体芯片；max_runs 是每 DAC 每 bank 的容量，各路不能借用，活动与待提交 bank 也不能相加。连续码段为原码与非零 u32 保持周期数；每条在 RAM 中占 `DAC_BITS+32` 个逻辑位，具体物理资源映射以对应 Vivado 构建报告为准。

默认并行固件 1/2/3～4/5～8 路分别为每路 8192/4096/2048/1024 个码段。主机必须按连接设备实际回报检查，不以离线默认配置覆盖。当前 STATUS 不含活动配置的码段总数，不能用当前播放索引推算空闲容量。准备/下载前的完整检查流程见[资源能力与下发检查](资源能力与下发检查.md)。

请求无负载。应答负载：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | 错误码 |
| 1 | u8 | 状态：0 IDLE、1 ARMED、2 RUNNING、3 DONE |
| 2 | u8 | 当前段，从 0 开始 |
| 3 | u16 | 所选波形的当前数字码 |
| 5 | u16 | 已完成循环数，采样播放器饱和于 65535，饱和后继续播放 |
| 7 | u32 | 当前配置 ID |
| 11 | u32 | 运行期间忽略的所选外部触发边沿数 |
| 15 | u8 | 是否有有效 active 配置 |
| 16 | u8 | 核心运行标记；能返回应答时为 1，失锁时复位不能应答 |
| 17 | u8 | 所选 DAC：0～7 对应 DAC 1～8 |
| 18 | u16 | 当前采样码段序号（完整 13 位），采样模式请用此字段而非偏移 2 |
| 20 | u8 | 0 旧分段模式，1 新采样模式 |
| 21 | u8 | 新模式触发输入号，从 0 开始；需能力位 bit0 |
| 22 | u8 | 新模式触发边沿：0 上升，1 下降；需能力位 bit0 |
| 23 | u8 | bit6 为当前活动配置来自上电快照（需 INFO bit4）；bit7 为 active 门控配置；bit2:0 为阶段，0 等待、1 进入、2 保持、3 正常返回、4 除法准备、5 提前线性返回、6 步长准备；需能力位 bit1 |

这是 FPGA 内部输出码状态，不是 ADC 测量。状态快照在一次解码时采集。

### 10 BEGIN

旧分段/FM 模式仅在 10 位固件可用；12/14 位固件拒绝 BEGIN。

只在 IDLE/DONE 接受，创建待提交的另一 bank，不改变正在使用的 active 方案。

| 负载偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u16 | 初始码 0–1023 |
| 2 | u16 | 更新分频 16–65535；200 MHz DAC 固件不再要求为 4 的倍数 |
| 4 | u16 | 段数 1–64 |
| 6 | u16 | 重复数 1–65535 |
| 8 | u32 | 主机分配的配置 ID |
| 12 | u8 | 0 软件、1 外部上升沿 |
| 13 | u8 | 保留，0 |
| 14 | u16 | 中止码 0–1023 |
| 16 | u16 | FM 初始码 0–1023 |
| 18 | u16 | FM 步长 0–1023 |
| 20 | u16 | FM 点数 1–1024 |

主机还检查 `fm_initial + fm_step*(fm_points-1) <= 1023`；设备的 FM 加法同时做饱和保护。

### 11 WRITE_SEGMENT

负载偏移 0：段序号 u16；2：目标码 u16；4：更新次数 u32，必须非零。

从第 0 段开始顺序发送。起点为 BEGIN 的初始码或上一段目标码。设备在下载时用迭代减法求出 `abs(target-start) / updates` 的商和余数。幅差最多 1023，所以最多约 1023 个计算周期；每条写段都要等待 ACK。

实际持续时间为 `updates * divider / core_hz` 秒。经过 N 个更新间隔后精确到达目标。每次更新后的码为 `start ± floor(abs(target-start)*k/N)`，k=1..N。重复或段间衔接不插入额外更新间隔。

### 12 COMMIT

全部段写入后才可提交。旧分段模式重复次数大于 1 时，最终目标必须等于初始码；采样模式允许循环边界跳变。切换 bank 后输出进入新初始码，FM 初始化；本次方案只有收到 ACK 才算下载成功。

### 20 ARM / 21 SOFT_TRIGGER

ARM 仅在 IDLE/DONE 且存在 active 配置时有效，预取描述符后才应答。外部模式在预取完成后接受新的所选边沿（旧分段模式仍为上升沿）；软件模式使用 SOFT_TRIGGER。外部模式下拒绝 SOFT_TRIGGER。

输入在布防前已经为高/低电平不会自行启动；需一个新的所选边沿。固定时长模式运行中的触发边沿不重启序列。INFO 特性位 bit3 为 1 时，固定时长外部触发在完成 repeat 轮后返回初始码并自动布防；FIFO 预取完成前的新边沿不排队。软件触发或旧固件结束后进入 DONE；配置中的 repeat 在每次触发内执行。电平门控的返回与自动重新布防规则见下文。

### 22 ABORT / 23 DISARM

ABORT 取消等待或运行，所选波形输出到 active 中止码；旧分段模式 FM 回到其初始码。DISARM 只取消非运行状态，新采样模式恢复初始码；RUNNING 时拒绝，避免把“取消布防”误当停止。

任何配置、布防、触发命令都不能与上位机另一实例并发使用同一设备。普通镜像上电及运行中逻辑复位会失去 active 配置，需重新下载；包含上电波形的镜像在 FPGA 完整配置后的首次启动恢复快照。逻辑复位不会重新装载 BRAM 初始化数据，详见文末上电扩展。


## 采样播放器扩展（30 / 31）

保持固定 32 字节帧和原命令兼容。主机先读取 GET_INFO 的 max_runs，旧固件返回 0 时禁止使用这些命令。

### 30 BEGIN_RUNS

| 负载偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u16 | 初始/完成码，0～(2^DAC_BITS−1)，桌面可设置 |
| 2 | u16 | 中止码，0～(2^DAC_BITS−1)，桌面可设置 |
| 4 | u16 | 连续码段数 1～8192 |
| 6 | u16 | 重复次数 1～65535；0 为无限重复，必须先确认 INFO bit6 |
| 8 | u32 | 配置 ID |
| 12 | u8 | 0 软件触发，1 外部触发 |
| 13 | u8 | DAC 号，从 0 开始，必须小于设备 DAC 数量 |
| 14 | u8 | 触发输入号，从 0 开始；扩展标志为 1 时使用 |
| 15 | u8 | 触发边沿：0 上升沿，1 下降沿；扩展标志为 1 时使用 |
| 16 | u8 | 扩展标志：0 兼容旧路由，1 使用输入号/边沿，其他值拒绝 |

主机仅在 GET_INFO 能力位 bit0 为 1 时设置扩展标志。标志为 0 时忽略偏移 14/15，使用与 DAC 相同编号的触发输入及上升沿，兼容旧客户端。输入号必须为 0～7，外部模式还要求小于实际输入数。旧设备不支持独立路由时，主机只允许同编号输入和上升沿，否则要求更新固件。

仅 IDLE/DONE 允许下载，不修改 active bank。两种 BEGIN 会替换同一个 pending 配置；不能交叉使用 WRITE_SEGMENT 和 WRITE_RUN。

无限模式只在最初等待所选外部/软件触发，之后末码段直接衔接首码段，不进入 DONE 或自动重新布防。ABORT 停止到中止码，取消布防仍只适用于等待状态。STATUS 负载 byte23 bit4 为活动无限配置标志（需 INFO bit6），可与 bit6 上电快照来源同时置位；运行状态以 byte1 为准。计数溢出不会结束播放。此 0 值仅用于 BEGIN_RUNS，不改变旧 BEGIN 或事件步骤次数的合法范围。

### 31 WRITE_RUN

负载偏移 0：码段序号 u16；2：原码 u16（0～2^DAC_BITS−1）；4：持续核心拍数 u32（1～4294967295）。从 0 顺序写入并等待每条 ACK，重复请求仅返回缓存，不重复写入。

完成后使用 12 COMMIT 原子切换 bank，再 20 ARM 预取。21 软件触发与 22/23 中止/撤防沿用状态限制。新模式的未选 DAC 固定为 2^(DAC_BITS−1)，即 512/2048/8192；只有所选 `trigger_in[输入号]` 的所选边沿才会启动波形，触发输入和 DAC 编号可独立设置。

每个描述符的原码保持 N 个 5 ns 周期。四项 FIFO 支持所有描述符均 N=1，无段间空拍。最后一轮结束返回初始码；循环间直接衔接第一描述符。顶层 DAC 数据寄存器统一增加一个固定时钟周期的管线延迟，不改变各采样点的保持时间。

所有位宽继续使用 u16 原码字段，帧长、CRC 和命令号不变。设备在写入 B 位存储前比较完整 u16 数值，越界返回参数错误，不截断高位。状态码字段也返回完整 u16。主机方案的 dac_bits 必须与 GET_INFO 一致；桌面在当前硬件配置下编辑方案时保持数值，不做位数比例换算。


## 电平门控扩展（32）

新增 BEGIN_GATE 0x32；两段采样表之间由外部高电平保持，下降沿返回并自动重新布防。完整负载布局、边界及提前返回公式见 [电平门控](电平门控.md)。


## 独立多路扩展（2026-09-11）

INFO 功能标志 byte 17 bit 2 表示独立多路。新增 0x40 通道选择和 0x41 原子分组控制，具体字段与操作见《四路DAC并行输出.md》。本次四路固件每路 2048 段，其他通道保持自身配置；旧文中的 8192 和未选通道中点行为属于旧单播放器固件。


### 自动布防和上电方案能力扩展

GET_INFO 的负载 byte17 新增 bit3 `fixed_auto_rearm`，bit4 `boot_profiles`。后者表示当前镜像包含上电方案。此阶段历史普通并行固件特性值为 15，包含上电方案时为 31；旧值 7 仍被上位机支持。后续功能扩展会增加能力位，当前值见上方 GET_INFO 表。

STATUS 负载 byte23 的 bit6 表示当前活动方案来自比特流初始化。bit7 和 bits2:0 仍为门控标记与阶段。普通 UART COMMIT 清除 bit6；ABORT/DISARM 不删除方案或清除来源标记。上电配置 ID 来自版本化方案指纹的 SHA256 前 32 位（小端，零映射为 1），详见 `host/boot.py`。上位机只有在能力位、来源位及所选保存版本 ID 均匹配时，才识别为匹配的上电方案。

自动布防是 FPGA 内部行为，不依赖串口轮询或上位机发送 ARM。状态中累计完成轮数在 65535 饱和，每次触发内另有独立计数器；取消布防或中止不会自动恢复运行。


## 单 DAC 多波形事件序列（2026-09-12）

新增 INFO bit5 与 byte18 步骤容量；`0x50 BEGIN_SEQUENCE`、`0x51 WRITE_STEP` 与原 WRITE_RUN/COMMIT 共同完成整表事务。固定时间表继续使用原 BEGIN_RUNS。此阶段历史多路功能值为 47，含上电快照时为 63；当前值见上方 GET_INFO 表。STATUS 的 byte23 bit5 标记活动事件序列，byte2 回报步骤，byte21 回报当前输入，byte22 包含当前边沿、阶段和 prepared。完整字段及兼容规则见 [执行序列使用说明](执行序列使用说明.md)。


## 触发步进扩展（0x33）

GET_INFO 载荷第 17 字节 bit7 表示原生触发步进能力。旧设备没有该位，上位机会在发送 BEGIN 前拒绝扫描下载。现有合法非扫描方案的 JSON 指纹不增加扫描字段，保持已有配置匹配。

`BEGIN_SCAN = 0x33` 使用 `struct <HHHhHIBBB`（17 字节，其余载荷补零）：

| 载荷字节偏移 | 字段 | 类型 |
|---|---|---|
| 0 | 首次触发前的等待码 | u16 |
| 2 | 中止码 | u16 |
| 4 | 扫描起始码 | u16 |
| 6 | 有符号步长 | i16，二进制补码 |
| 8 | 点数，含起点 | u16，1～65535 |
| 10 | 配置 ID | u32 |
| 14 | DAC 通道 | u8，从 0 开始 |
| 15 | 触发输入 | u8，从 0 开始 |
| 16 | 标志 | bit0 外部触发、bit1 下降沿、bit2 循环，其余为 0 |
| 17～23 | 保留 | 必须为 0 |

多路固件先 SELECT_CHANNEL，BEGIN_SCAN 的 DAC 编号必须与所选通道一致。BEGIN_SCAN 只写待提交参数，不改变当前 DAC 输出；不发送 RUN。COMMIT 原子提交并进入空闲，输出等待码；ARM 从头等待触发。软件模式使用 TRIGGER，每条去重后的命令只推进一次。ABORT 返回中止码，DISARM 返回等待码。末点保持模式完成后状态为 3，循环模式继续保持状态 1 等待下一次边沿。

设备对原码范围、步长、点数、输入、保留位以及 `起点+(点数−1)×步长` 的有符号终点做校验。DAC 位数为 B 时，原码范围为 `0～2**B−1`，步长为 `−(2**B−1)～+(2**B−1)` 的整数；起点与末点都必须在原码范围内。点数上限 65535 来自当前协议的 u16 字段，不在 INFO 中单独回报，也不受 max_runs 波形码段容量约束。步长为 0 时可以配置 65535 个相同码值的扫描点。

错误或未提交的事务不会替换生效配置。多路 GROUP ARM/TRIGGER 继续沿用原有整组预检查，准备扫描与其他波形使用同一事务流程。

STATUS 扩展：载荷第 23 字节 bit3 为扫描模式，扫描时 bit4 为循环标志；此时它不是普通波形无限重复标志。载荷第 18～19 字节为本轮已输出点数（0 表示尚未输出起点），第 22 字节 bit7 为就绪。完成轮数沿用 16 位 loops，65535 饱和；原码、通道、配置 ID、触发输入/边沿沿用原有字段。

上电配置 BOOT_CONFIG 每 DAC 256 位：bit5 为扫描，bit6 为扫描循环；[207:192] 为起始码槽，[223:208] 为有符号步长，[239:224] 为点数。初始/中止码、配置 ID、输入及边沿沿用原槽位；扫描不读取波形 BRAM。重新上电会重置点进度，时钟异常复位不会自动恢复可能已被 UART 改写的旧启动配置。

## 分段线性插值扩展（0x34 / 0x35 / 0x52）

本扩展保持协议版本 1、固定 32 字节帧及所有旧命令含义。它需要新增固件能力，不能向旧 `BEGIN_RUNS` 发送线性目标表代替升级。下文所有 byte 偏移都从 **24 字节负载首字节**开始计算；完整帧偏移须加 6。

### 能力、状态与旧固件

GET_INFO 的 byte19 bit0=`interpolation`；byte20 为最短插值段拍数，本实现 32；byte21 为插值语义修订号，本实现 1。byte19 bit1 / bit2 及 byte22～23 另用于批量上传和 USB 能力，见上方能力表。主机仅在插值能力为真、修订号为 1、最短拍数不小于 32 时接受插值能力；未置位的旧固件按不支持处理。

`max_runs`（INFO byte13～14）同时表示该通道每 bank 的保持 / 插值描述符槽数。四路仍为 2048；活动与待提交 bank 不相加，也不能跨通道借用。新模式存储仍为 `DAC_BITS+32` 位，14 位时为 46 位。

STATUS byte20 bit0 保持原采样模式含义，bit1 新增当前插值播放器标志；事件序列该位随当前步骤变化。非事件插值模式使用 STATUS byte22 bit7 回报 `prepared`，其余原边沿字段保留；事件序列沿用原 byte22 的就绪 / 阶段布局。ARM 在准备完成后 ACK；就绪前的新触发不排队。

准备 / 下载先重新读取 INFO，整批方案通过位数、模式、步骤容量、描述符容量及完整精度检查后才允许开始写入。旧固件收到 `0x34`、`0x35`、`0x52` 应返回错误 1“不支持”，主机不得降级成旧保持命令。支持新模式的固件继续原样接受旧保持方案。

### 0x34 BEGIN_LINEAR

负载与 `0x30 BEGIN_RUNS` 完全相同：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0、2 | u16、u16 | 初始 / 完成码、中止码 |
| 4、6 | u16、u16 | 插值段数、重复次数 |
| 8 | u32 | 配置 ID |
| 12、13 | u8、u8 | 外部触发标志、DAC 编号 |
| 14、15、16 | u8、u8、u8 | 输入编号、边沿、路由扩展标志 |
| 17～23 | 字节 | 未使用，发送方置零 |

适用于单个固定波形和纯插值固定时间表。重复次数 0 表示无限播放，仍要求已有 INFO byte17 bit6 无限重复能力。有限外部触发完成一批后自动重新布防；软件触发完成进入 DONE。初始码和中止码不改为描述符目标值。

### 0x35 BEGIN_LINEAR_GATE

负载与 `0x32 BEGIN_GATE` 完全相同：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0、2 | u16、u16 | 初始 / 完成码、中止码 |
| 4、6 | u16、u16 | 总插值段数、进入插值段数 |
| 8 | u32 | 配置 ID |
| 12、13 | u8、u8 | DAC 编号、触发输入编号 |
| 14 | u16 | 高电平保持目标码 |
| 16 | u32 | 返回持续拍数，正常返回表之和也必须等于此值 |
| 20～23 | 字节 | 未使用，发送方置零 |

依次写入全部进入描述符和全部返回描述符，保持阶段不存表。上升沿启动、完成进入后保持目标、下降沿启动正常返回、返回完成自动重新准备。进入阶段的提前下降继续使用既有“捕获当前原码、B+1 拍准备、按设置返回拍数线性回初始码”语义和幅差向下取整算法，不使用预设正常返回函数。详见 [14 位高斯分段插值](14位高斯分段插值.md)。

### 0x52 BEGIN_SEQUENCE_LINEAR 与 0x51 WRITE_STEP

`0x52` 与原 `0x50 BEGIN_SEQUENCE` 使用相同负载：偏移 0/2 为初始 / 中止码 u16，4/6 为共享波形池段数 / 步骤数 u16，8 为配置 ID u32，12 为 DAC 编号 u8，13～23 必须为零。

`WRITE_STEP` 仍为 `<BBBBHHHHIIHH` 的 24 字节布局，仅最后 u16，即 **负载 byte22～23**，新增 bit0：

- bit0=0：该步骤的 `(原码, 拍数)` 按原恒码保持语义播放，可使用 1 拍段。
- bit0=1：该步骤的 `(目标原码, 拍数)` 按线性插值语义播放，每段至少 INFO byte20 拍。
- 其他位必须为 0。原 `0x50` 事务仍要求整个末字段为 0，不能通过旧 BEGIN 激活新模式。

共享波形池允许保持与插值步骤混合，地址 / 段数 / 门控分界仍按每步给出。相同描述符值但不同播放模式或初始码不能混用去重键；合法相同波形可被多个步骤及不同输入引用，按实际唯一池段数检查容量。各步骤的就绪、输入路由、忽略忙时触发、完成推进及门控提前返回规则保留。

### WRITE_RUN、整数输出与事务验证

沿用 `0x31 WRITE_RUN`：偏移 0 为段序号 u16，2 为目标原码 u16，4 为持续拍数 u32。完整 u16 目标先做 DAC 位数范围检查，不能截断后接受。14 位 BRAM 字布局为 `[45:32]=target, [31:0]=ticks`，不附加每段斜率字段。

某段从 S 到 E 持续 N 拍，起点取初始码或前段目标。正常表段发出 `k=0…N−1`：

```text
code[k] = S + floor(((E−S) × k + floor(N/2)) / N)
```

除法向负无穷取整；等价于理想直线四舍五入，半码向较大 DAC 原码取整。负斜率也使用此定义。下一段直接发出它的 k=0，不增加一个终点或等待样本。原码中间值由新整数插值执行器生成；旧 sample_engine 仍是恒码保持播放器。

N 最小为 32，最大为 `2^32−1`。提交线性模式前检查所有被线性步骤引用的描述符是否符合最短时长，门控另检查进入最后目标、最终返回目标和返回时长之和。任何失败返回参数错误 3，不完整事务返回 4，均不切换 active bank。计算参数提前准备；最短段不足不允许通过插入隐藏时钟解决。

固定时间表当前只接受全保持或全插值，不接受混合。全插值子波形必须回到共同初始码；非零等待至少 32 拍。它们由主机在发送 BEGIN 前检查，不静默转换原波形。

### 保存与启动镜像

JSON 新字段为 `playback="linear"` 与 `interpolation_error`（默认 1 个原码，允许显式 0）。旧方案缺失字段按 `hold` / 1 读取，默认旧方案的序列化与指纹不增加字段。误差是对原完整取整采样逐点比较的差异；并非模拟电压精度，也不由固件宣称函数精度。

每 DAC 的 `BOOT_CONFIG` bit7 表示单波形插值，或事件程序允许线性步骤；事件程序的逐步播放模式仍来自步骤最后 u16 bit0。原 bits0～6、其他参数槽位及 `.mem.steps` 大小不变。14 位 `.mem` 每字仍 46 个逻辑位，四路每文件 4096 行初始化覆盖双 bank，而单次有效波形池容量仍是 2048。

启动镜像由主机使用同一完整编译及容量检查生成。USB / 串口上传不改变 Flash；必须重新构建并另行固化，掉电后才恢复新快照。原发布参考固件没有此扩展，旧上电快照继续保持原输出语义。

## 高速 USB 与批量上传扩展

启用 FT232H 的固件同时保留 UART。USB 与 UART 的解析器分别完成 CRC 校验，内部路由一次向控制器提交一条请求，再把应答返回该请求的来源。切换接口无需运行时模式命令，但上位机应先断开旧接口、再连接并读取能力和状态。启用 USB 不改变 BRAM 容量、保持 / 插值模式或触发语义。

### 36 RUN_BATCH

仅在 INFO byte19 bit1 为 1、byte22=1 且 byte23 在 1～3 范围时使用。没有批量能力的旧固件继续逐条接收 `0x31 WRITE_RUN`；不因 USB 连接本身推断支持新命令。

| 负载偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u16 | 第一段索引，必须等于当前已接收段数 |
| 2 | u8 | 本批数量，1～3 且不超过固件回报上限 |
| 3 | u8 | 保留，必须为 0 |
| 4、10、16 | u16 + u32 | 逐条原码及非零持续拍数；保持模式为恒码，插值模式为目标码 |
| 其余字节 | 0 | 包括未使用的描述符槽位及偏移 22～23 |

固件先验证整批原码、时长、顺序和剩余容量，任何字段失败均不写入该批。合法批次依序写待提交 bank 后返回应答，全部批次通过仍须 COMMIT。单波形插值批次拒绝小于 32 拍的段；混合事件池在 COMMIT 时依据各步骤模式验证引用的段。旧逐段写入命令保持兼容。

USB 上传窗口最多 16 帧 / 512 字节，仍为每条请求核对对应命令、序号、CRC 和错误码；写入不完整、缺少应答或任一状态失败均不得 COMMIT。窗口失败不自动重发整窗，因为设备只缓存最近一条事务，不能保证重放整个窗口无副作用。断开重连后可重新 BEGIN 并完整下载。UART 保持一条请求对应一条应答。

本版未启用外部 DDR3 存储能力，不提供 `0x03 INFO_MEMORY`。若连接到曾使用 byte19 bit3 的未发布 DDR3 测试固件，主机明确拒绝，以免错误解释其容量或最短段规则。接口设置及引脚见 [高速 USB 与串口](高速USB与串口.md)。
