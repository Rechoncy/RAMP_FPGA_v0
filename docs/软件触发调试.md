# 软件触发调试

入口：左侧 **系统调试 → 触发调试**。静态原码输出保留在同一页面的另一标签中。

## 使用步骤

1. 连接设备并下载所需方案，方案触发源仍选“外部触发”，选择对应触发输入。
2. 在输出控制页布防需要调试的 DAC，然后进入触发调试页，选择方案使用的触发输入。
3. **直接发送电平或脉冲**，不必先手动接管。软件自动暂时取消原先等待中的通道布防，接管所选输入，再恢复这些通道的布防并等待就绪，最后发送触发；已加载波形和配置标识保持不变。也可先用“接管所选输入 · 保留布防”或“接管全部输入”准备来源，这两个按钮不会发送触发。未布防的通道不会自动开始播放。
4. 固定波形、触发步进使用“发送单脉冲”。门控波形使用“设为高电平”进入并保持，“设为低电平”返回。单脉冲也可检查提前下降后的返回。
5. 周期触发设置高电平时间、周期、次数，再点击“开始周期脉冲”；次数为 0 时显示“无限循环”。周期必须严格大于高电平时间。
6. 完成后点击“结束调试”。软件中止全部 DAC、输出各自已提交的中止码、恢复物理触发。需要重新布防后，物理触发才能继续实验。

首次接管会短暂输出原方案的中止码，重新布防会将扫描/事件序列进度和计数从头开始。只在需要切换来源时执行此过程，已经接管后的连续高/低电平操作不会反复布防。若有通道正在播放，拒绝切换来源；先停止通道再操作。仅接管所选输入会将其他输入恢复物理来源；需要分别控制多个输入时先选择“接管全部输入”。

同一输入对应的多路 DAC 接收同一个 FPGA 时钟拍的边沿；不同输入可分别设置静态电平。目前只有一套周期脉冲发生器，同一时刻只能运行一路脉冲列。脉冲运行期间拒绝新的电平或脉冲操作；可随时结束调试。

## 时序与状态

- FPGA 产生边沿，电脑只下发参数。点击至第一个边沿仍有 USB/UART 和系统调度延迟，不能作为与电脑同步的精密时间基准。
- 高、低持续时间以当前核心时钟整数拍计数，125 MHz 时为 8 ns/拍。界面显示量化后的拍数；非零时间不足半拍而取整成 0 时拒绝执行，不暗中拉长。
- 高电平拍数、周期拍数范围为 1～4,294,967,295；周期模式至少保留一个低电平拍。已有播放器在忙时的触发规则保持不变，超快脉冲不保证每个脉冲都执行波形。
- “已产生上升沿”是发生器计数（32 位累计，溢出回绕），与 DAC 完成次数不同。各 DAC 的状态、原码、完成次数、忽略触发数来自设备回读。重复“设为高电平”不会额外制造上升沿。
- 脉冲个数只计算上升沿；如果方案使用下降沿，也会接收对应的下降沿。高电平保持不是重复启动波形。
- 已接管输入屏蔽物理引脚边沿，未接管输入保持物理来源。切换来源不产生虚假边沿。

## 断开与恢复

调试期间上位机每次后台轮询发送心跳。FPGA 约 3 秒收不到所属接口的有效心跳或调试动作时，会停止发生器、中止全部通道，再恢复物理来源。另一接口的状态查询不会替原调试会话续期。

正常断开会尝试主动结束调试；通信完全断开时由 FPGA 超时处理。在这约 3 秒内，之前的电平或脉冲可能继续，因此它不是急停硬件的替代品。

调试接管、运行状态不随设置保存，也不会写入 Flash。保存的仅是输入选择、时间、单位、脉冲次数。编译或下载新的波形前需结束调试，以免长操作阻塞心跳。

旧固件、旧双输出引擎及当前演示设备不支持此真实触发模块时，界面会禁用操作；不会将新的触发命令降级为其他含义。现有软件触发 0x21 和演示设备模拟边沿继续保留。

## 验证边界

数字原码回读和 RTL 逐拍仿真不等于 DAC 引脚实测或模拟电压测量。实板验证记录另存于本次验证报告；仅临时加载 BIT，不自动改写 Flash。断电后仍启动此前固化的固件。
