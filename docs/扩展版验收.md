# 初始值、触发与 DAC 扩展版验收

> 本文记录之前的固定 10 位扩展版。当前可变位宽版本见 [DAC 位宽版验收](DAC位宽版验收.md)。

日期：2026-09-10。工具：Vivado 2023.1、Icarus Verilog、Python 3.12 专用虚拟环境。器件：`xc7a35tfgg484-2`，参考时钟 50 MHz，核心及 DAC 200 MHz。

## 功能验证

`python -m pytest tests -q`：**46 passed**。随后针对演示器取消布防返回初始码的修正，扩展测试单独复验 **9 passed**。

- 初始码进入 Ramp 计算、函数 I 变量、编译缓存、协议下载及结束返回；中止码独立生效。
- 通道、触发输入和边沿独立保存、下载与回报；错误输入/边沿不启动，运行中触发不重启。
- 参数化 RTL 测试覆盖 DAC/触发数量 1/1、4/8、8/4，逐路检查所选输出、未选通道 512、重复播放、完成、中止及非法配置拒绝。
- 同步器测试覆盖上电输入高/低时不产生伪边沿，以及后续真实上升/下降沿。
- GUI 演示闭环覆盖 4 DAC / 3 输入、DAC 3 由输入 1 下降沿触发、初始 300、中止 444；缩小再扩大数量保留引脚/时序，移除所选通道后明确报错。
- 旧板卡 JSON 迁移、旧方案默认触发映射、旧固件能力回退、逐路时序覆盖和 XDC 端口生成均有测试。

## 时钟模型

XSim 使用生成的 MMCM 和 UNISIM ODDR 模型：2 路与 8 路均报告 **PASS DAC200**。检查 5 ns 周期、2.5 ns 高电平、通道时钟对齐及共享时钟边沿的数据寄存。8 路测试为每路注入不同数字码，检查全部 80 个数据位。

复验 8 路时钟模型：

```powershell
& 'E:\Software\Xilinx\Vivado\2023.1\bin\vivado.bat' -mode batch -source scripts/vivado/check_dac200_sim.tcl -tclargs build/studio_expansion8/ramp_studio.xpr 8 8
```

## 验证边界

这些是核心时序和数字行为检查，不是板级验收。模板尚缺 UART 管脚和 DAC min/max 输出延迟；8 路模板还缺新增的 DAC/触发管脚。DRC 如实保留 NSTD-1、UCIO-1，8 路还有部分总线未锁定管脚的 PLIO-3 提示。没有降低 DRC 严重性，没有生成或烧录 bitstream。

完整系统需要在页面填入实际接线、电压、DAC 时序，重新执行完整实现并检查，再做上板测量。多 DAC 同时播放不同波形不在当前实现中；当前为从 1～8 路中选择一路播放，其余保持 512。

源码哈希及报告位置保存在 `build/validation_expansion_manifest.json`，最新索引为 `build/validation_manifest.json`。前一版指标仅适用于历史工程，见 [函数播放器验收](函数播放器验收.md)。
