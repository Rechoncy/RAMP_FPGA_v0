# 单幅度 Ramp、自定义函数与 DAC 输出

新版上位机、协议和 RTL 均独立位于 `host/`、`rtl/`、`scripts/vivado/`。构建只读取这两个 RTL 目录、页面导出的 XDC，以及现场生成的 Clocking Wizard IP；不读取 `Assistant_FPGA/` 的源码、IP、工程或检查点。原资料仅用于参考板卡封装与默认引脚模板，换板可在子页面修改。

## 单幅度 Ramp

选择“单幅度 Ramp”，设置一个**目标幅度码**与渐变、保持、返回三个时长。设置“初始 / 结束码”和“中止码”，输出从初始码渐变至目标，保持后返回初始码。例如初始 300、目标 700，过程为 300 → 700 → 300。码值减小时电压升高，码值增大时电压降低。

位数可在硬件页面选择 10/12/14 bit，详见 [DAC 位数设置](DAC位数设置.md)。下表为原 10 位板卡的已知特性。

全程使用 DAC 原码，不假定 ±5 V 等电压范围，不进行电压标定或线性电压换算：

| DAC 原码 | 已知电压方向 |
|---:|---|
| 0 | 最大正电压 |
| 512 | 接近零 |
| 1023 | 最小电压，为负 |

新模式提交配置后、布防时和完成时为已设置的初始码，中止时为中止码；取消布防恢复初始码。独立多路固件中，其他通道继续自身输出；旧固件中未选通道为当前位数的数字中点（512/2048/8192）。普通镜像上电或运行中逻辑复位后输出该中点码，配置失效需重新下载；含上电快照的镜像在完整重配置后恢复对应方案，详见 [Flash 固化与启动](Flash固化与启动.md)。512 是“近零”，不是经过测量的精确 0 V。

## 哪个 DAC 输出

一个方案只控制一个所选 DAC；当前支持 1～8 路可选输出。通道号对应下面的 FPGA 接口，物理插座需要依据板卡原理图确认。

| 上位机选择 | 10 位配置的数据总线 | 200 MHz 输出时钟 |
|---|---|---|
| DAC 1 | `dac_data[9:0]` | `dac_clk[0]` |
| DAC 2 | `dac_data[19:10]` | `dac_clk[1]` |
| DAC 3 | `dac_data[29:20]` | `dac_clk[2]` |
| DAC n（1～8） | `dac_data[10*n-1:10*(n-1)]` | `dac_clk[n-1]` |

触发输入独立选择：输入 n 对应 `trigger_in[n-1]`，可选择上升沿或下降沿。DAC 3 可以由输入 1 的下降沿启动，无需相同编号。默认模板前两路时钟为 Y8/R14，前两个触发输入为 F13/F14；这些是参考板卡的映射，换板须核对。

在“板卡与连接 → 板卡信息”设置数量，在独立的“引脚配置”页填写逐位数据引脚和时钟/触发引脚。修改数量或接线后需要重新生成 XDC、构建并烧录。连接后软件使用设备实际报告的数量；不会仅因修改页面就假定板上已经增加 DAC。

切换通道、初始值或触发设置后必须重新下载才能布防。正在运行时不能替换已提交配置。接线和扩展步骤见 [初始值、触发与 DAC 扩展](初始值触发与DAC扩展.md)。

## 自定义函数

`f(t)` 直接返回当前位数范围内的实数 DAC 码值（10/12/14 位最大值分别为 1023/4095/16383），软件自动取整。`I` 是“初始 / 结束码”输入值；`t` 和 `T` 的单位为**秒**，右侧时长输入单位为 **ms**。`T` 是四舍五入到完整时钟周期后的单次总时长。

示例：

```text
I - 400*sin(2*pi*t/T)
I - 400*exp(-((t-T/2)/(T/8))**2)
where(t < T/2, 112, 912)
clip(I + 600*sin(2*pi*t/T), 0, 1023)
```

支持 `sin/cos/tan/exp/sqrt/log/abs/minimum/maximum/min/max/where/clip`，以及 `I`、`pi`、`e`。幂写 `**`，指数限 0～16 常量。分段函数用 `where`，禁止导入、属性访问、任意 Python 代码、列表和文件操作。

计算规则：

1. `N = floor(时长秒 × 200000000 + 0.5)`。
2. 采样点 `t[k] = k / 200000000`，`k = 0 … N−1`；相邻点间隔 5 ns。
3. 每点计算 `c[k] = floor(f(t[k]) + 0.5)`；输出必须有限且在当前位数的原码范围内，超范围报错，不隐式截断。可显式使用 `clip`。
4. 将连续相同的整数码合并为 `(码值, 持续拍数)`，无损下载到 FPGA。每个码持续精确的拍数，FIFO 预取支持连续每拍更换码值。
5. 第 N 拍之后返回初始码；重复模式直接开始下一轮的第 0 点，不插入额外拍。最后一轮结束才回到初始码。

量化误差至多 0.5 LSB。`t=T` 不在采样数组中：它是播放完成、返回初始码的边界；因此函数末点不必等于初始码，边界处可以发生用户设计的跳变。零渐变时长允许直接跳至目标；零返回时长在结束时直接回到初始码。

## 容量、检查和预览

编译器一次最多 8192 个连续码段，实际下载按 INFO 的每路容量检查（当前四路为 2048 段/路）；单次最多 1 秒（2 亿个采样点）；循环次数最多 65535。低频 Ramp 的大量相同码值可压缩，因此不会要求存放几千万个独立采样字。高频连续变化的函数可能很快耗尽 8192 个码段，程序会明确报错，**不会自动改变 200 MHz 采样率**。

预览最多显示 1600 个抽样位置，可能无法展示高频细节，也不能据此判断容量和全域合法性。“完整离散检查”与下载都会遍历全部 5 ns 采样点，报告容量超限、NaN、无穷和越界。完整检查和下载在后台线程运行；长波形的计算和串口传输需要时间。

## 独立构建

从“板卡与连接”生成新的工程。当前实现适配 Xilinx 7 系列，其他厂商需要各自时钟/DDR IO 适配器与构建工具；通用函数播放器没有厂商原语。实际 DAC 的 200 MHz 接收能力与 IO 建立/保持仍需按板卡资料填写，并在板上验证；内部时序通过不能代替此项验收。
