# Flash 固化与启动

入口：左侧 **板卡与连接 → Flash 固化与启动**。

## 设置

- Flash 型号：填写 Vivado 完整配置存储器型号，扫描可加载 Vivado 的 SPI 型号库。JTAG 扫描只列出 FPGA，不会自动识别 Flash 芯片。
- 容量：以 MiB 为单位，128 Mbit = 16 MiB。
- SPI 位宽：SPIx1 / SPIx2 / SPIx4，须与实际接线、Flash 型号及比特流启动设置一致。
- 配置时钟与边沿：只影响 FPGA 从 Flash 加载的启动阶段，与运行时 200 MHz DAC 时钟不同。
- JTAG：硬件服务器、具体目标和 FPGA 器件。扫描发现多块板卡时，请明确选择目标。
- 比特流：选择 `.bit`。每次操作保存输入文件快照及 SHA256。
- 预期 USR_ACCESS：可选的 8 位十六进制固件标识。留空时仅检查 DONE 和 CRC；不能据此证明正在运行的是某一指定版本。

“填入本机已验证 Flash 参数”填入当前板卡此前验证过的 `mt25ql128-spi-x1_x2_x4`，容量 16 MiB，SPIx1，16 MHz、下降沿。换板时按实际芯片填写，不能直接沿用预设。此前四路固件的 USR_ACCESS 为 `09112040`；重新构建后应使用新固件自己的标识。

点击“保存到板卡配置”后，Flash 参数随板卡 JSON 导入、导出。SPI 启动参数会写入生成的 XDC 和构建流程；更改后需要重新生成比特流。把已有 `.bit` 转为 MCS 不会修改已有比特流内部的 SPI 位宽和配置时钟。

## 操作顺序

1. 设置参数、选择比特流，可先点击“生成 MCS / BIN”，该操作无需 JTAG，也不改动硬件。
2. 断开上位机串口，扫描并选择 JTAG 目标和器件。
3. “临时下载 .bit”只配置 FPGA RAM，掉电失效。
4. “备份并固化 + 校验”先校验比特流 FPGA 型号、Flash 容量与位宽，再加载烧写辅助电路。默认读取整片备份，备份成功且大小正确后才擦写启动镜像；随后进行 Vivado 校验与 BIN 逐字节读回比较。启动地址固定为 0，不配置 MultiBoot。
5. 固化成功后 FPGA 仍运行烧写辅助电路，点击“从 Flash 重启”，重新加载固件并检查 DONE、CRC 和可选固件标识。
6. 将开发板启动跳线设为正确的 Master SPI 模式。完全断电再上电后，可点“只读检查启动状态”；该按钮不下载比特流，以免掩盖冷启动问题。

固化会中断 DAC 输出，进行中的擦写不能断电。备份开关可关闭，按钮会明确显示“不备份”。不匹配、备份失败或校验失败不会显示成功；操作失败后请检查日志，FPGA 可能仍为烧写辅助配置。

所有设置快照、MCS/BIN、`previous_flash.bin` 整片备份、读回文件和日志位于 `user_data/flash_jobs/时间戳/`。每次使用独立目录，保留历史备份。

## 上电波形与自动布防

1. 在“方案设计与保存”中保存波形，在各 DAC 页面选择保存版本及触发设置。在本 Flash 页独立勾选纳入范围，不使用输出控制总览的临时勾选。
2. 在本页点击“纳入上方所选方案”，查看每路的快照。该操作仅保存到板卡 JSON，不改变硬件。后续编辑方案不会自动更新快照，需再次纳入。
3. 进入构建，选择“实现与 bitstream”。工作进程按 200 MHz 完整离散、四舍五入并校验各路容量，生成 `*_boot/boot_manifest.json`、RAM 初始化文件和独立顶层。构建通过后，`.bit` 自动填入 Flash 页面；生成工程、综合或核心检查本身不会生成可烧写比特流。
4. 执行备份并固化、校验，再从 Flash 重启。配置存储器载入固件的同时初始化播放 RAM，各路自动布防。外部触发方案无需连接电脑；软件触发方案等待软件命令，不会自行输出。
5. 完整断电重启后，连接串口只回读状态即可。DAC 页面显示固化方案匹配状态，无需重新下载。配置 ID 用于版本识别，不是波形存储器的逐字节回读证明。

未纳入的 DAC 上电保持数字中点（10/12/14 位分别为 512/2048/8192）。不会默认为它们选择其他通道的波形。

本实现把上电波形初始化数据放在 FPGA 比特流内，复用现有双缓冲播放 RAM，不增加 SPI 用户管脚。Flash 保存固件和明确纳入的波形快照，完整方案库仍保存在电脑的 `user_data`。**普通串口下载仅临时替换 RAM，不自动写 Flash；要永久更新波形，必须重新纳入、构建并固化。** 关闭程序、断开串口不会清除已经下载的 RAM 波形；完整重配置后恢复的是 Flash 中的快照。

仅发生时钟失锁/逻辑复位而未重新配置 FPGA 时，固件取消布防并清除活动配置，避免用已经被 UART 改写的 RAM 搭配旧的上电参数。此时需重新下载，或从 Flash 完整重配置；不将逻辑复位误当作一次完整 Flash 启动。

固定时长外部触发：完成 `repeat` 轮后返回初始码、清空预取队列并自动重新布防。预取需要数个核心周期（每周期 5 ns），期间以及运行中的新边沿不排队。已就绪后的触发由 FPGA 硬件处理，另有输入同步和输出寄存器延迟，不能理解为零延迟。重复次数是每次触发内的轮数，状态中的完成次数累加并在 65535 饱和；手动 ARM、DISARM、ABORT 会重置计数。软件触发仍为单次任务完成后进入 DONE，需再次 ARM；电平门控维持原有自动重新布防行为。

更换板卡需重新生成适配该板 FPGA、引脚、位数和通道数的固件；目前 GUI 构建适配器支持 Xilinx 7 系列。不能把本板的比特流或 Flash 参数直接用于其他型号。

## 验证范围

自动重新布防已覆盖重复次数、连续事件、逐个 5 ns 样本、忙时触发、中止和取消布防。上电初始化仿真覆盖 10/12/14 位、四路配置隔离、门控返回、未触发通道、UART 替换与时钟复位保护。Flash 擦写的 Tcl 故障测试覆盖容量/FPGA 型号不匹配、备份失败和读回不一致。

具体固件的布局布线、烧写及冷启动结果以交付目录内的验证记录为准；源码测试不能代替实板掉电验证，数字逻辑状态不能代替 DAC 模拟电压和外部时序测量。
