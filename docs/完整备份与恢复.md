# 完整工作区备份与恢复

私有仓库的 [2026-09-19 完整备份 Release](https://github.com/Rechoncy/RAMP_FPGA_v0/releases/tag/workspace-backup-20260919) 保存本机完整工作区快照，补齐普通源码提交中排除的文件。需要登录有权限的 GitHub 账号才能下载。

包含：源码与手册、当前 EXE/BIT、完整 `release/`、两处 `user_data/`、历史 `archive/`、全部 `build/`、原始 `Assistant_FPGA/`、`.venv/`、Vivado 与 Python 缓存、日志和快捷方式。只排除根目录 `.git/` 内部元数据；Git 提交历史另以 `repository.bundle` 保存。没有将目录中已有的文件清理或删减后再备份。

Git 主分支继续管理源码；完整快照通过同一私有仓库的 Release 附件保存，避免大文件限制。仅 `git clone` 不会下载 Release，完整恢复还需执行以下步骤。

1. 从上述 Release 下载所有 `RAMP_FPGA_v0-full.zip.001`、`.002`……分卷，以及 `BACKUP_INDEX.json` 和 `Restore-FullBackup.ps1`，放在同一个目录。具体卷数和逐卷校验值以 `BACKUP_INDEX.json` 为准。
2. 在该下载目录打开 PowerShell，执行 `powershell -ExecutionPolicy Bypass -File .\Restore-FullBackup.ps1 -Destination D:\RAMP_FPGA_restored`。目标文件夹必须尚不存在，脚本不会覆盖已有实验数据。
3. 脚本先校验每卷 SHA256，合并 ZIP、校验整体 SHA256，然后解压并逐文件验证。`FULL_BACKUP_MANIFEST.json` 记录每个原文件的相对路径、大小、修改时间和 SHA256；分卷是一个 ZIP 的原始字节片段，不能单独解压。
4. 日常运行打开恢复目录中的 `release\Ramp Studio.exe`；EXE 旁的 `release\user_data` 保留原实验设置。源码模式的数据位于根目录 `user_data`，不要将两处数据互相覆盖。

`.venv`、Vivado 工程和快捷方式可能含原电脑绝对路径，保存了原始文件并不意味着能在任意新路径直接运行。EXE 可便携使用；新电脑开发时按《仓库使用说明》重建 `.venv`，重新设置 Vivado 路径并生成工程。驱动、Vivado 安装、系统 Python 以及项目文件夹之外的数据不在本次工作区备份范围。

Release 还单独提供当前软件便携 ZIP 和 R2 固件 ZIP，便于仅下载日常运行所需内容。固件快照不代表板卡 Flash 已固化；此前验证只临时加载 FPGA，恢复电脑文件不会改变板卡硬件。

完整备份含本地实验方案和设置，应继续保持仓库私有。`repository.bundle` 可用 `git clone repository.bundle <新目录>` 恢复已提交源码历史；它不替代上述工作区分卷。
