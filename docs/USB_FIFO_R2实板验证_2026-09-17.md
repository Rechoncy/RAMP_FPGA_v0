# USB FIFO R2 实板数字验证 · 2026-09-17

用户接入 USB SLAVE 后，已对上一轮 UART 验证所用的 **R2、四路 10 位、125 MSPS** 固件完成 USB FIFO 数字联调。**本轮没有重新烧写 FPGA、Flash 或 FT232H EEPROM，也没有修改驱动和用户方案文件。** 所有测试结束后，四路均为空闲原码 512、未布防，USB 连接已释放。

## 如何使用

在新版 Ramp Studio 的“板卡与连接”刷新设备，选择 **USB FIFO · FTAE79DQ**，然后连接。USB FIFO **无需设置波特率**；当前 Windows 枚举出的 COM5 是该 FT232H 的虚拟串口入口，测试使用的是独立 D2XX FIFO 入口，不要用 COM5 代替 USB FIFO 选项。

继续沿用 `FPGA-XC7A35T-AutoBaud-20260917-R2/125MSPS/ramp_studio.bit`，无需为切换 USB 接口重新生成 BIT。UART 和 USB FIFO 由同一份固件支持，软件一次选择一个接口连接。

上一轮仅通过 JTAG 临时加载 R2 `09171830`，**Flash 仍未改写**。掉电或从 Flash 重新加载会恢复原 Flash 固件；届时需要重新加载对应 BIT，才能保证继续使用该版本的 USB FIFO、125 MSPS 和自动波特率功能。

## 实测检查与传输速度

本轮主测试 **334 项检查通过**，另有 **3 次重连检查通过**。测试将单帧重试次数设为 1，即每个请求只发一次；批量窗口也不重发，没有依靠自动重试隐藏通信失败。

- 连续 256 个窗口，每窗口 16 帧 INFO，共 **4096 帧**，约 0.512 秒，逐帧检查 CRC、命令、序号及应答状态。
- 四路静态原码 504、508、516、520 的通道隔离回读正常。
- 四路各下载并提交完整 2048 个描述符，确认有效标志与配置 ID；这组满容量数据不触发播放。
- 四路同时播放逐码保持波形，再同时播放线性插值波形；均完成两轮，观察到各路目标平台，最终返回 512。
- 无限重复正常；故意损坏 CRC 的中止帧被忽略，正常中止返回 512。
- 四路门控方案布防、Input 1 / Input 2 分配回读和取消正常。这部分没有施加外部物理门控信号。
- 清理完成后三次重新打开 D2XX 连接，固件能力和四路空闲状态保持一致。

本轮 USB FIFO 每路约 **90 ms**，相对上一轮 UART 1M 的相同规模提交约快 **6.7 倍**。每路有效描述符数据 12,288 字节，对应约 **136.6 kB/s**；这是包含 BEGIN、应答与 COMMIT 的应用层实测吞吐量，不含函数编译，也不是 USB 总线线速或其他电脑的速度保证。

USB 只改变下载和控制接口，不增加 BRAM 容量，不改变 125 MSPS 输出时钟、采样间隔或波形时长。

复现时先确认匹配的板卡和固件，并让各通道空闲。以下命令会覆盖 FPGA 暂存波形，使用 504～520 原码，结束恢复四路 512；不会烧写 FPGA、Flash 或 EEPROM：

```powershell
.\.venv\Scripts\python.exe scripts\verify_usb_device.py --port usb:FTAE79DQ --execute-hardware --expected-core-mhz 125 --info-windows 256 --output build\new_usb_r2_check.json
```

334 项包含播放过程中重复查询到的原码范围检查，执行快慢可能改变这些检查的条数；4096 个窗口查询帧和四路满容量提交规模固定。

本次是实际 USB 通信和 FPGA 数字状态回读，**没有测量 DAC 模拟电压、物理逐拍输出或外部触发边沿**。输出时序仍沿用 R2 的实现报告与器件典型参数约束，本次通信通过不扩大原有时序和模拟精度结论。
