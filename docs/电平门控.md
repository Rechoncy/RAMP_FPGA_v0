# 上升沿进入 · 高电平保持 · 下降沿返回

工作台现在可选择“固定时长”或“电平门控”。旧方案默认保持固定时长行为。

## 使用

1. 选择单幅度 Ramp，或三段自定义函数（例如高斯）。
2. 设置初始 / 结束码、目标幅度码、进入时长和返回时长；各时间仍可选择 ns / µs / ms / s。
3. 选择“电平门控”，选择输出 DAC 和外部触发输入。固定保持时长隐藏，重复次数和触发边沿选择禁用。
4. 下载方案、布防，再向所选输入送上升沿。
5. 上升沿开始进入段；进入完成后，高电平持续多久就继续保持多久。下降沿开始返回段，结束回到初始码，并自动等待下一次上升沿。

演示设备提供“模拟上升沿”和“模拟下降沿”两个按钮，可观察进入、保持、返回及完成次数。演示用系统时间，不是纳秒级时序测量。图中的平台标有“示意”，实际保持长度由触发决定。

例如：进入 70 ms，返回 70 ms，外部高电平 500 ms。忽略固定管线延迟后，前 70 ms 进入，随后约 430 ms 保持，下降沿后用 70 ms 返回。高电平保持时间不需要预先输入，也不占用波形存储。

## 提前下降沿

如果进入段还没结束就发生下降沿，FPGA 锁存此时的输出码 C，不跳到目标码。随后从 C **线性返回**初始码 I，返回时长使用已设置的返回时长。正常完成进入段后才按所选返回函数（例如半高斯）返回。

提前返回需 B+1 个核心周期准备整数步长，期间保持 C。10 / 12 / 14 位分别为 55 / 65 / 75 ns，之后每 5 ns 更新一次，经过 N 个周期精确回到 I：

`C + sign(I-C) * floor(abs(I-C) * k / N)`，k=1…N。

预先编译的进入 / 正常返回表按原码四舍五入，误差不超过 0.5 LSB；提前线性返回采用上述整数累加公式，相对理想直线误差小于 1 LSB，终点精确等于初始码。

上述时间以 FPGA 同步后的边沿事件为起点；物理触发还经过输入同步，DAC 引脚经过一个固定输出寄存周期。所有触发响应均由 FPGA 执行，Python 只负责编译、下载和监测。

## 连续触发规则

- 布防时输入已为高电平不会直接启动，需要新的上升沿。
- 进入 / 保持 / 返回期间的新上升沿不重启，计入忽略数；返回期间的下降沿不改变返回。
- 返回完成后自动预取并重新布防，完成计数到 65535 饱和，继续运行。返回完成后为下一上升沿预留至少 50 ns；过早边沿不排队。
- “取消布防”用于等待状态，恢复初始码；运行中使用“中止”，输出已下载的中止码并停止自动布防。串口命令有通信延迟。
- 修改方案需先取消布防或中止，再下载。断开电脑不会停止硬件门控。

进入、返回各至少一个 5 ns 周期，合计不超过 1 秒；两段合计最多 8192 个连续码段，超限报错，不降采样。高电平保持没有固定超时。支持 10 / 12 / 14 位，同一固件统一位数；独立多路固件支持同时播放，各路保持自身配置；旧固件每次一个所选 DAC 播放。四路实板的每路上限为 2048 个连续码段，以设备 INFO 回报为准。

## 实际接线与固件升级

在“板卡与连接”设置触发输入管脚、对应 IO 标准和输出 DAC 数据 / 时钟管脚，再生成新版工程、完成实现并烧录。两个边沿来自**同一根所选触发线**。外部信号与 FPGA 共地，使用匹配的逻辑电平。

200 MHz 输入同步会漏掉过短脉冲；现有接线说明建议高、低电平各至少 20 ns，实际可靠脉宽和响应延迟须在板上测量。门控的连续上升沿还需满足前一段返回完成及重新预取时间。

仅更新 EXE 不会更新板上逻辑。上位机读取固件能力位，不支持门控的旧固件会明确提示升级；固定时长仍可使用。未填写完整 UART 管脚、DAC 建立 / 保持时序时只能生成工程及核心检查，不能据此确认整板时序或生成可用烧录文件。

## 协议扩展

GET_INFO 负载偏移 17 的 bit1 表示支持门控。新增 `0x32 BEGIN_GATE`，24 字节负载按小端布局：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u16 | 初始 / 结束码 |
| 2 | u16 | 中止码 |
| 4 | u16 | 总连续码段数，2…8192 |
| 6 | u16 | 进入段连续码段数，1…总数−1 |
| 8 | u32 | 配置 ID |
| 12 | u8 | DAC 通道，0 开始 |
| 13 | u8 | 触发输入，0 开始 |
| 14 | u16 | 保持目标码 |
| 16 | u32 | 提前线性返回周期数，1…200000000 |
| 20 | 4 字节 | 保留，0 |

发送进入段的全部 RLE，再发送返回段的全部 RLE，使用已有 `0x31 WRITE_RUN` 和 `0x12 COMMIT`。相同原码也不能合并跨越两段的边界。主机使返回表拍数之和与偏移 16 一致；正常返回由表中拍数决定，提前返回由偏移 16 决定。没有保持表，重复数固定为单周期事件，硬件自动重新布防。

状态沿用 IDLE / ARMED / RUNNING / DONE；门控循环完成进入 ARMED。GET_STATUS 负载 23 的 bit7 是 active 门控标志，低三位标识阶段，见 [协议 v1](协议-v1.md)。旧客户端仍能读取原状态字段，但要使用门控必须升级客户端与固件。
