# UART 自动波特率实板验证 · 2026-09-17

本轮使用达芬奇 XC7A35T 板卡、Digilent JTAG 与板载 CH340（COM3），目标为四路 10 位、125 MSPS、两路触发、每路 2048 个码段的自动波特率固件。用户授权临时 JTAG 下载及数字联调，本轮不改写 Flash。

## 初始状态与发现的问题

JTAG 首次回报器件 `xc7a35t`、用户标识 `09171701`，DONE=1、配置 CRC 错误=0。串口回报原固件仍为 200 MHz、无 UART 自动识别能力，四路均空闲并输出原码 512。

加载上一轮新生成的 125 MSPS BIT 后，能力回读正确，但实板 921600 和 1M 不能同步。9600、19200、38400、57600、115200、230400、460800 可以连接。首次验证失败的报告保存在 `build/uart_live_20260917/uart_validation.json`，已执行清理并恢复四路中间码；未将仿真通过替代为实板通过。

## FPGA 内部诊断与修复

为避免依赖示波器，生成了临时串口诊断固件，保持四路静态原码 512、DAC 时钟 125 MHz，使用独立固定 115200 的查询链路读取 FPGA 捕获的 64 个串口边沿间隔。该镜像只用于诊断，不作为最终播放器发布。

FPGA 以 125 MHz 核心时钟拍记录得到：

| 主机选择 | 数据位间隔 / 拍 | 部分字节末尾高电平 / 拍 | 原识别器结果 |
|---|---|---|---|
| 115200 | 1076～1078 | 与正常位间隔相同 | 锁定 |
| 460800 | 268～270 | 与正常位间隔相同 | 锁定 |
| 921600 | 134～135 | 269～270 | 未锁定 |
| 1,000,000 | 123～125 | 248～249 | 未锁定 |

高速档位在字节之间出现约两个位时间的高电平，即在一个停止位之外多留一位空闲。原识别器要求 24 个连续等间隔，把这些合法空闲看成另一个速率或无效间隔，不断清空累计结果。记录在 `build/uart_live_20260917/scope_measurements.json`。

修复后的识别器在已观察到九个稳定间隔（一个起始位及八个数据位）之后，允许字节之间的长高电平空闲；空闲本身不计入有效间隔。仍需累计 24 个同档位有效间隔才准备锁定，低电平异常、短数据串和速率改变会清空累计。保留 10 ms BREAK 门槛、250 ms 训练超时以及 TX 完全空闲后切换分频的规则。软件仍发送原来的 20 ms BREAK 和 16 个 0x55。

新增仿真覆盖额外 1～4 位的字节间空闲，以及不足一个完整字节的间断脉冲不能累积为有效训练。正常无间隙发送与旧固定波特率接收器的行为继续回归检查。

## 低速首包等待修复

R2 FPGA 加载后，1M 连续 128 次 INFO 已无重试，但第一次降至 9600 时首个 INFO 仍需内部重试。CH340 的 `flush()` 返回不能作为最后一个训练字节已经离开 UART FIFO 的证明。现在软件在 flush 后，额外等待完整训练串的保守发送预算 `16 × 12 / baud` 秒，再加 `max(10 ms, 24 / baud)` 的线路空闲等待，然后才发 INFO。各档位等待预算均有测试；连接时只执行一次，不降低后续传输速率。

该中间失败保存在 `uart_validation_fixed.json`；修复后整套测试从头重跑，没有用内部重试掩盖首包失败。

## 最终实板结果

已通过 JTAG 临时加载完整 R2 播放固件，用户标识 **09171830**，DONE=1、配置 CRC 错误=0。诊断镜像已被替换。最终报告为 `build/uart_live_20260917/uart_validation_final.json`，**53 项检查通过，3549 次正常命令交换、0 次重试**，另有一次故意发送的错误 CRC 帧。检查包括：

- 同一份 BIT 连续切换全部九档波特率；1M 两轮各连续查询 128 次，其余速率每轮查询 24 次，均正确应答。
- 四路静态码与配置 ID 在连接切换后保留。
- 四路同时连续播放，分别使用 Ramp / 高斯、逐码保持 / 线性插值；多次以 9600、115200、921600、1M 重新训练后，运行状态、配置 ID 和递增的循环计数正常。
- 错误 CRC 的中止帧被忽略，正常群组中止返回原码 512。
- 1M 下四路分别完整下载并提交 2048 个码段，耗时为 0.603、0.603、0.605、0.604 秒。这项满容量数据只检查提交，不播放。
- 测试结束后四路均为空闲原码 512；最后以 115200 重新连接只读确认，见 `final_status.json`。

软件使用时，在“板卡与连接”**断开 → 选择波特率 → 连接**即可，无需再次烧写。当前 FPGA RAM 中为 125 MSPS（8 ns/点）、四路 10 位、两路触发、每路 2048 段。**本轮没有写 Flash；掉电或从 Flash 重新加载会恢复 Flash 原有版本，自动波特率能力不保证保留。** 本 BIT 未包含用户上电波形，复位为空闲 512、不自动布防。

Vivado 2023.1 对四路 10 位、125 MSPS、USB FIFO + UART 配置完成综合、布局布线及 BIT 生成，使用 R1 布局作增量参考，未放宽时钟、DAC 和 USB 约束：

| 项目 | R2 结果 | 相对 R1 |
|---|---|---|
| LUT | 13,070 / 20,800（62.84%） | +36 |
| FF | 16,267 / 41,600（39.10%） | +6 |
| BRAM | 32 / 50（64%） | 不变 |
| DSP | 4 / 90（4.44%） | 不变 |
| WNS / WHS | +0.091 / +0.054 ns | 通过 |
| USB bus skew | 通过 | 原约束保留 |

最终源码的回归结果为 **700 项通过、1 项跳过**（691 项其他软件/RTL 检查，加 9 项自动波特率 RTL 检查）。跳过项是 Windows 无原生符号链接创建权限的可选用例，相关路径保护与 NTFS junction 用例仍运行。Flash 模拟测试首次整组执行出现 Tcl 标准句柄跨 pytest 捕获边界失效，单例通过；将测试解释器生命周期限制在同一次捕获暂停内后，相关 38 项 Flash/串口测试通过。修复仅改变测试夹具，没有对硬件 Flash 执行任何操作。初始失败与最终记录均保留。

新版 EXE 在含中文、空格的迁移目录，移除 Python/Qt PATH 依赖后，通过 offscreen 与 Windows 两组启动和工作区检查。源文件、测试结果、BIT、板卡配置与实现证据分别位于：

- 固件包中的 `125MSPS/board.json`、`board.xdc`、`resource_report.json`、`final.dcp` 与各项时序/资源报告；`source_snapshot.zip` 包含本次源码和测试，`验证记录/` 包含实板与回归证据。

## 测量范围

串口应答经过帧长度、CRC16、命令和序号检查，重发次数单独记录。DAC 原码、循环次数、配置 ID 和运行状态来自真实 FPGA 回报，不能等同于测量了引脚上的每个输出采样点或 DAC 模拟电压。未使用受控外部触发源验证物理触发边沿，也没有接入示波器。

本轮只枚举到 COM3 数据串口和 JTAG 下载器，没有枚举到 USB FIFO 数据设备。USB FIFO 的真实传输不在本轮实测范围；其 RTL 与软件回归另行执行。

后续用户切换连接后，同一 R2 固件的 USB FIFO 补测已通过，见 [USB FIFO R2 实板验证](USB_FIFO_R2实板验证_2026-09-17.md)。上述 UART 阶段的原始记录保持不变。
