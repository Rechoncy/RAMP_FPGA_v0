# Ramp Studio · Windows 便携版

输出采样率可选 100 / 125 / 200 MSPS；3PD5651E 使用最高 125 MSPS。详见 [采样率设置](输出采样率与3PD5651E.md)。切换需重新构建和烧录，替换 EXE 不会改变板上时钟。

## 文档入口

完整操作步骤和界面截图见同目录《软件详细使用手册.html》，开发阶段、验证结果和版本边界见《开发日志.html》。便携包中这两份离线文档位于 `文档/` 子目录，双击即可在浏览器阅读；Markdown 源文档和历史验收记录也随包提供。

## 双击启动

解压 `Ramp-Studio-Windows-x64.zip` 到可写的本地文件夹，双击 **Ramp Studio.exe**。
蓝白波形图标已嵌入 EXE，桌面快捷方式不需要单独的图标文件。
上位机自带 Python、Qt、NumPy 和串口模块，无需安装 Python，也不需要原 FPGA 工程。
首次启动会解包运行库到系统临时目录，因此可能需要几秒钟。

本版本目标为 **Windows 10/11，x64**。macOS、Linux、32 位 Windows 需要各自重新构建；未宣称在所有电脑或 FPGA 上已验证。

## 退出自动保存

正常退出会将设置与编辑进度保存到 `user_data/desktop_session.json`，下次启动恢复板卡 / Flash 输入、波形 / 序列 / 扫描草稿、时间单位、DAC 分配、Debug 待提交原码、首选串口及连接波特率和上次界面位置。无效或尚未完成的参数也保留为草稿；有效板卡设置同时写入 `board.json`，无效输入不会覆盖已有有效配置。写入失败时显示原因并保留窗口，处理后可再次关闭。

自动保存草稿不更新方案库中的保存版本。需要让 DAC 使用修改后的波形时，仍须点击对应“保存方案”，再准备目标 DAC。启动保持未连接，不自动下载、布防或应用静态输出；Debug 恢复的数字是待提交输入。

## 全局保存与导入

左侧 FPGA 信息下方提供“全局保存”和“全局导入”。全局保存先提交当前输入并保存会话，再导出一个 `.ramp-workspace` 文件，包含整套方案库、未保存草稿、板卡 / 引脚 / 时钟 / USB / UART / Flash 设置、上电方案快照、DAC 分配、Debug 待提交值及界面设置。它保留草稿，不自动更新供 DAC 选择的保存版本。

在新电脑启动最新版 EXE，保持未连接，点击“全局导入”并核对包摘要后即可恢复。导入替换当前方案及配置，之前的工作区自动备份到实际 `user_data/archive/workspaces/`；随后工作区重新打开，保持未连接，不自动下载、布防或应用静态输出。恢复旧工作区时，在同一入口选择自动备份包。

工作区包不含 EXE、Vivado、生成固件、硬件 Flash 内容、日志、Flash 作业记录、构建缓存、历史归档、资源报告及报告选择，也不包含设备确认缓存。导入保留接收端这些已有文件，并按恢复的板卡配置重新检查本机报告匹配关系；导入文件不作为设备已下载确认。外部文件只保存路径文本，迁移后需要重选实际位置。只传方案和设置时，复制便携 ZIP 加工作区包即可；需要完整历史记录时，继续复制整个 `user_data`。操作和准确路径见 [迁移到其他电脑](迁移到其他电脑.md)。

## 迁移实验与设置

最省心的方式是完整复制 **`E:\Github_Project\RAMP_FPGA_v0\release`** 文件夹到新电脑，例如 `D:\RampStudio\release`，双击其中的 EXE。若要传输较小的文件，则复制 `release/Ramp-Studio-Windows-x64.zip` 加现有的整个 `release/user_data`，将 user_data 放在解压后的 EXE 旁。便携 ZIP 不含本机实验数据。逐项清单、准确文件夹名称和摆放示例见 [迁移到其他电脑](迁移到其他电脑.md)。

- 程序默认把方案、板卡配置、窗口设置、运行日志保存到 EXE 旁的 `user_data`。
- 换电脑时关闭程序，将 **Ramp Studio.exe 与整个 user_data 文件夹一起复制**。仅复制 EXE 会使用初始示例方案。
- 不要把工作文件夹放进 `Program Files` 等受限目录。如果首次运行时程序所在目录不可写，会使用 `%LOCALAPPDATA%\RampStudio\user_data`；界面“打开数据目录”可查看实际位置，该目录也需要一并备份。
- 已有 `user_data` 无法写入时会明确报错，避免误以为历史方案丢失。可将整个文件夹复制到可写位置后重试。
- 高级部署可通过环境变量 `RAMP_STUDIO_DATA_DIR` 显式指定绝对数据路径；普通便携使用无需设置。
- 移动目录后，旧 Windows 快捷方式不会自动更新；重新为 EXE 创建快捷方式即可。

## 连接硬件与生成工程

演示模式不依赖 Vivado、串口设备或网络。实际连接 FPGA 仍需对应 USB-UART 驱动，并在软件中选择新电脑上的 COM 端口以及所需波特率（旧固件须匹配其固定速率）。连接期间速率不可更改，先断开后再设置。

使用 FT232H 高速 USB 时，另安装 Windows x64 FTDI D2XX 驱动，连接板卡独立 USB SLAVE 插口，在设备列表选择 `USB FIFO · 序列号`。启用 USB 的同一份固件保留 UART，软件选择一个入口连接；切换时先断开，USB 不使用波特率选项。FT232H 需已配置为 245 FIFO 模式，程序不会自动改写 EEPROM。USB 参数和引脚随 `user_data` 或全局工作区包迁移，驱动需在新电脑单独安装。详情见 [高速 USB 与串口](高速USB与串口.md)。

串口预设支持 9600～1,000,000 baud、8N1。新版固件通过连接时同步自动识别所选档位，正常切换只需断开、选择波特率、重连。旧固定波特率固件须先升级一次；只替换 EXE 不会升级板上固件。“板卡信息 → UART 上电默认波特率”保持默认 115200 即可，连接时不受它限制。参见 [UART 自动波特率](UART自动波特率.md)。

1M 是每秒 1,000,000 波特，不是 1 MB/s；此设置不改变 DAC 播放时钟。R2 已在当前 CH340 上完成九档实板数字检查，四路 125 MSPS 播放期间重连正常；新电脑的 USB-UART 和驱动也须支持所选速率。使用 `FPGA-XC7A35T-AutoBaud-20260917-R2` 固件包；当前板卡已临时 JTAG 加载该版本，Flash 未改写。详见 [UART 实板验证](UART实板验证_2026-09-17.md)。

只有生成、综合或实现固件时需要另外安装 Vivado（以及器件支持/所需许可证）。在“板卡与连接”页面重新选择当前电脑的 `vivado.bat`，本机原路径 `E:\Software\Xilinx\Vivado\2023.1\bin` 不能代替新电脑的安装位置。

工程输出保存在 `user_data/builds`。EXE 内包含独立 RTL 和 Vivado Tcl；每次构建将源码展开到同目录的 `studio_时间_sources`，不会引用临时解包目录，也不依赖 `Assistant_FPGA`。

迁移后建议使用保存的板卡配置重新生成工程；旧 Vivado 工程可能保留旧电脑的绝对路径。构建路径避免 `% & | < > ^ !` 等命令字符；Vivado 构建建议使用较短的英文路径。

200 MHz、10/12/14 位、通道/触发数量和引脚配置仍受实际板卡、DAC 接口与时序约束限制。打包 EXE 不会改变已经验证的固件行为或自动适配未知板卡。

参考时钟可选单端或差分以及 50 / 100 / 200 MHz；时钟 IO 标准、差分终端及 P/N 引脚随板卡 JSON 保存。相关 RTL 和生成脚本已包含在 EXE。更换参考输入需按新板卡重新生成固件；当前构建适配器支持 Xilinx 7 系列。详见 [参考时钟配置](参考时钟配置.md)。

门控新版支持上升沿进入、高电平保持、下降沿返回，详见 [电平门控](电平门控.md)。请先保存方案、关闭旧窗口，再用新版 EXE 启动；实际板卡需要重新生成并烧录新版固件。

## 诊断与重新打包

程序启动异常时会显示提示，并尽可能写入 `user_data/startup-error.log`。构建日志保存在数据目录的 `build_时间.log`。

发布验证可运行：`"Ramp Studio.exe" --self-test "诊断目录\report.json"`。此命令只测试内置演示设备，在报告旁创建独立 `check_data`，不会连接真实硬件。

源码目录执行 `Build-Executable.ps1` 可重新打包；依赖固定在 `requirements.txt` 与 `requirements-packaging.txt`，资源列表在 `RampStudio.spec`。输出位于 `release`，包含 EXE、ZIP 和 SHA256 校验值。第三方许可随 `licenses` 目录提供；PySide6/Qt 上游源码与许可见 https://code.qt.io/ 。保留源码和构建脚本可重建、替换依赖版本。

此包没有代码签名证书。Windows 下载信誉提示不等同于程序缺少依赖；部署环境要求签名时，需要使用组织自己的代码签名证书签名。

## 方案设计与 DAC 控制

左侧“方案设计与保存”管理波形；“输出控制”显示各 DAC 的已加载缩略图和批量操作。点击 DAC 进入单路大图，展开“方案与触发设置”选择本地方案，点击“准备 DAC n”完成检查、按需下载和布防。可切换“已加载波形 / 本地方案 / 版本对比”。总览操作勾选通道，单路操作当前 DAC，Flash 有独立勾选。

编辑草稿和保存方案相互独立：未保存编辑不会进入 DAC 页或影响硬件。保存新版本后，旧下载不会被当作新版本，须重新下载确认。Debug 返回初始码使用所选 DAC 的保存方案，未选择时禁用。

迁移时正常关闭程序，复制整个 `user_data`，包括 `profiles`、`desktop_session.json`、`designer_draft.json`、`sequence_draft.json`、`scan_draft.json`、`parallel.json`、`loaded_waveforms.json`、`flash_selection.json`。旧版 `dac_editors.json` 保留。可通过“恢复历史草稿”读取旧通道草稿及归档的设计草稿；历史分段只读打开，三段结构可转换为新的 Ramp 副本，检查后再保存。启动不再自动恢复旧编辑器，FM 扫描输入已移除。迁移时保留 `user_data/archive` 中的草稿备份。

Flash 固化入口位于“板卡与连接 → Flash 固化与启动”，支持型号/容量/SPI 设置、生成 MCS/BIN、备份固化、读回校验与启动检查，详见随包的《Flash固化与启动.md》。

首次升级时，Flash 独立选择优先从已有上电快照纳入通道初始化；没有上电快照时从旧勾选配置迁移一次。之后仅使用 Flash 页自己的选择。


## 触发步进

独立入口位于“方案设计与保存 → 触发步进”，保存后在 DAC 页选择并准备。迁移整个 user_data 时会携带扫描方案与 scan_draft.json。此功能需要支持触发扫描的新 FPGA 固件；EXE 更新不会自动烧写板卡。详见同目录《触发步进使用说明》。
