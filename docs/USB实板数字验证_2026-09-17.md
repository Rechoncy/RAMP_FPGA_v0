# USB FIFO 实板数字验证 · 2026-09-17

已将 USB FIFO + UART 双接口诊断固件 **09171701** 通过 JTAG 临时下载到 XC7A35T，完成 FT232H 数据接口的真实数字联调。**未写 Flash，断电后仍启动原 Flash 固件 09112040。** 测试结束四路均为原码 512、未布防，电脑端连接已关闭。

## 1. 本次配置与时序假设

| 项目 | 本次配置 |
|---|---|
| FPGA / DAC / 触发 | xc7a35tfgg484-2 / 4 路 10 位 / 2 路 |
| 参考 / 核心 / DAC / USB 时钟 | 50 MHz 单端 / 200 MHz / 200 MHz / 60 MHz |
| USB 数据接口 | FT232H，序列号 FTAE79DQ |
| JTAG | Digilent，序列号 210512180081 |
| UART | 固件保留 115200；本次没有连接独立 USB UART，未重复实测串口 |
| 存储 | 每路每 bank 2048 段 BRAM，活动与待提交容量不相加 |
| DAC 采样边沿 | 默认上升沿 |
| 诊断输出延迟 | min **−0.5 ns** / max **1.0 ns** |
| 固件上电内容 | 无内置实验波形；四路等待码 512 |

延迟值是本次诊断假设：先按 DAC 保持时间 0.5 ns、建立时间 1.0 ns 处理，尚未计入未知走线差。它们可保存并重复使用，**不是对所有 DAC 和板卡永久有效的参数**。输出延迟反映外部接收器的建立／保持时间和板级时钟、数据偏斜，不是串口或软件通信延迟。参见 [AMD 输出延迟定义](https://docs.amd.com/r/2023.2-English/ug1387-acap-hardware-ip-platform-dev-methodology/Defining-Output-Delays)。

在“板卡与连接 → DAC 时序”增加“填入诊断默认值”按钮；逐路覆盖仍优先。当前电脑的 `release/user_data/board.json` 和退出会话已保存 USB 引脚及上述默认值，下次启动可继续使用，实验方案和 Flash 上电快照保留。原文件备份于 `build/usb_hardware_20260917/user_settings_before/`。软件不会自动连接或布防。

## 2. 实现和 JTAG 结果

本次复用 9 月 16 日已核验源码和已布线 DCP，先核对哈希，再补入四路 DAC 的上述输出约束。最初出现 −0.795 ns 保持违例，经过物理优化和重新布线后才生成 BIT；没有通过放宽时钟或删除约束使其通过。

| 最终检查 | 结果 |
|---|---|
| 全局 setup / hold | **+0.001 / +0.058 ns** |
| 脉宽裕量 | +1.370 ns |
| DAC 输出最差 setup / hold | +0.066 / +0.068 ns（基于假设延迟） |
| LUT / FF | 12,959 / 16,240（62.30% / 39.04%） |
| BRAM36 / DSP | 32 / 4（64.00% / 4.44%） |
| DRC | 0 错误，4 条扫描 DSP 输入流水建议 |
| USB Gray 指针 bus skew | 四组均通过，最小裕量 +4.219 ns |
| JTAG 回读 | USR_ACCESS=09171701，DONE=1，CRC_ERROR=0 |

建立裕量仅 0.001 ns，不能推广到其他位数、通道数、引脚或重新布局。CDC 的两条复位组合输入告警继续保留：它们进入三级异步置位／同步释放链；未隐藏告警或称为全部清零。Gray 指针及 FIFO 数据跨时钟约束沿用已核验设计，并在本次最终布线后重新检查。

最终时序包含这次假设的 DAC 输出约束，但未知器件的真实建立／保持时间没有因此得到确认。静态时序通过也不等于模拟电压或全部环境条件通过验证。

## 3. USB 实测结果

**85 项数字检查全部通过**，包含：

- 实际读取四路、10 位、200 MHz、2048 段和 USB／批量／插值能力。
- 四路分别输出 504、508、516、520，并通过 FPGA 状态核对通道隔离。
- 8 组、每组 16 帧 INFO 窗口，共 128 帧，检查 CRC、序号和应答状态。
- 各路实际下载并提交 2048 个描述符；这组满容量数据只下载，不触发播放。
- 四路逐码保持与线性插值波形各播放两轮，观察目标平台、计数和返回初始码。
- 无限重复、软件中止返回 512；门控模式布防、触发输入分配与取消。
- 结束四路恢复 512、空闲；随后断开并重连 3 次，状态一致。

| 满容量下载 | DAC 1 | DAC 2 | DAC 3 | DAC 4 |
|---|---|---|---|---|
| 描述符数 | 2048 | 2048 | 2048 | 2048 |
| BEGIN 至 COMMIT 耗时 | 90.512 ms | 90.019 ms | 89.998 ms | 90.051 ms |

每路有效描述符为 12,288 字节，相当于本次操作约 136 kB/s 的描述符有效吞吐量；包含命令应答开销，不含波形函数编译，也不是 USB 总线物理带宽。后续测试、其他电脑和驱动可能不同。四路分次上传，不能把这个结果解释为四路模拟输出同步偏差测量。

FT232H 的 128 个 EEPROM 字在联调前后读取一致，未改 EEPROM 或驱动。发现 Digilent JTAG 下载器也会枚举为 FT232H，现已从数据接口列表排除其专用设备描述，避免误设置 FIFO 模式。相关主机／配置回归 42 项通过，最终 EXE 三组便携检查通过。

用户选择暂不使用示波器，因此本轮没有模拟电压、实际 DAC 管脚波形、200 MHz 时钟边沿或外部触发脉冲测量。门控测试是布防／取消；正常及提前下降沿的实物返回过程未在本轮施加受控外部信号测试。
